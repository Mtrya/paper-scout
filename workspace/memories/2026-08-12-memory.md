## 猜想(已检验):RynnValue 的防捷径设计让价值函数内容接地——成立,且多尺度回退检测是意外收获
- type: hypothesis
- keywords: RynnValue, 价值基础模型, cost-to-go, 进度估计, 数帧捷径, 时序打乱, value-isolation attention, 内容接地, 回退检测, RL credit assignment, 机器人数据筛选
- status: tested-confirmed(核心)/部分证伪(防捷径不完全:frozen 时序泄漏)
- confidence: medium-high(shuffle ρ=0.76 为硬证据;单一视频/任务、4B 档位为边界)
- scope: 一切"视频前缀→剩余时间/进度"的价值模型;做 RL 信用分配、重试片段标注、数据过滤的人
- source: runs/2026-08-12-rynnvalue-shortcuts-ouroboros/rynnvalue-2608.09853/(probe_rynnvalue.py 与三份 JSON)

### 检验与结果
官方 RynnValue-4B 真实加载(官方 prefix 协议,16 帧重采样),同一 28.5s 视频八条件扰动,逐前缀 150 点:
- shuffle:ρ(v,末帧真实剩余)=0.76 vs ρ(v,位置)=-0.03——位置信息被物理摧毁后相关性只剩内容来源,数帧捷径确实被打掉。
- reversed:v 0.40→10.44 单调升(ρ=0.69);truncate90%:终点 v=2.37 vs 正向 0.38(近完成敏感)。
- rewind 30%:回退腿 v 上跳 5.3s;loop 10%×3(加密采样):每次重播精准上跳 +2.3/+3.9s,循环后回落,终点 0.44≈正向 0.38——**价值函数能识别动作回退,小尺度校准良好**,这是论文没展示、对 RL credit 与数据标注最实用的性质。
- frozen40/80:画面冻结后 v 仍以近正向斜率惯性下滑——残留时序先验泄漏,防捷径不完全(部分捷径签名);但冻结终点读数仍高于正向,内容对绝对水平的影响还在。
- 绝对校准压缩:读数天花板 ~10s vs 真实 28.5s,曲线噪声大非单调——读排序信号可以,读绝对秒数需重新校准。

### 推论
- 开源、可加载、内容接地的价值基础模型,可直接进数据工厂流水线(RL credit、重试标注、进度过滤)。
- 评估"防捷径"类设计声明,shuffle+倒放+冻结+回退这组扰动是可复用的最小压力测试包;shuffle 的 ρ 对比(内容 vs 位置)是最硬的单项证据。

- type: hypothesis
- keywords: RynnValue, 语言头 verifier, Success 判定, 假阴性, 视频描述, 数据过滤, 任务完成判定
- status: tested-confirmed(单案,两种 max_new_tokens 复现)
- confidence: medium(单视频单任务;模式清晰:描述停在"放入容器",不提"关抽屉")
- scope: 任何用 VLM 语言头当 verifier 做数据过滤/成功判定的管线
- source: runs/2026-08-12-rynnvalue-shortcuts-ouroboros/rynnvalue-2608.09853/(probe_results_extra.json analysis 字段)

### 发现与推论
正确指令下 Match=Yes、错误指令 Match=No(匹配可靠),但 Success=No——而末帧任务确实完成。max_new_tokens 128→256 复跑判定不变,排除截断伪影;自生成描述两次都停在"把盒子放进木容器",从不提关抽屉。Success 信号建立在模型自己的描述上,描述系统性漏掉收尾动作。**用语言头当 verifier 做数据过滤时,假阴性惩罚的恰恰是描述里没被说出来的那部分任务**;过滤管线应优先用价值头(数值信号)而非 Success 布尔位,或对 Success 假阴性做人工抽检校准。

### 检验与结果

### 推论

## 执行:启智平台下载权重的路径选择——大文件走 ModelScope,小文件 hf-mirror,直连最慢
- type: execution
- keywords: inspire, 启智, Hugging Face 下载, hf-mirror, ModelScope, 断点续传, HF_HOME, 缓存目录
- outcome: working
- verified: 2026-08-12
- applies-when: 启智 notebook 上下载 HF 权重/数据集
- invalidated-by: ModelScope 无对应镜像(AI-ModelScope 命名空间缺该模型,报错 record not found)
- source: 本轮 rynnvalue-probe notebook 实操

### 做法与坑
1. 直连 huggingface.co ~800KB/s;hf-mirror 对大文件(3.3GB siglip)会 IncompleteRead 中断,需重试循环;**ModelScope(AI-ModelScope/<name>)几分钟下完 3.3GB,首选**;但命名空间覆盖不全(clip-vit-base-patch16、dinov2-base 在 AI-ModelScope 不存在),小文件(<1GB)退回 hf-mirror 可接受。
2. modelscope 的 CLI 是 `.venv/bin/modelscope download --model <id> --local_dir <dir>`,不是 `python -m modelscope`。
3. HF_HOME 指向 workroot 缓存;`.incomplete` 断点文件同 hash 可跨缓存目录复用(cp 到目标 blobs 目录即续传)。
4. 探针脚本加 `ENCODER_ROOT` 环境变量做"本地目录优先,否则 HF id"的解析,避免重复下载。
5. SiglipProcessor 需要 sentencepiece,venv 里漏装会在加载时才报错——启动前检查。

## 执行:RynnValue 推理的坑(num_frames 默认值 OOM、use_meta、transformers 版本)
- type: execution
- keywords: RynnValue, pred_slot_isolated_eager, OOM, num_frames, use_meta, robot_description, transformers 版本, trust_remote_code
- outcome: working
- verified: 2026-08-12
- applies-when: 加载 RynnValue 或同类自定义 attention 的 VLM 做批量前缀推理
- invalidated-by: 官方仓库更新默认配置
- source: runs/2026-08-12-rynnvalue-shortcuts-ouroboros/rynnvalue-2608.09853/

### 做法与坑
1. `pred_slot_isolated_eager` 会物化全量注意力矩阵:batch×num_frames 一大就 OOM(47GB 卡上 batch4×64 帧要 56GB)。probe 脚本默认 num_frames=64 是陷阱,必须显式传 16(或 8)。
2. 模型 config `use_meta=True`:processor.process_episode 必须传 robot_description/camera_description,否则报错或行为漂移。
3. 远程代码(value_tokenizer.py 等)ModelScope 权重目录没放,要从 GitHub repo 的 `rynn_value/*.py` 补齐;transformers 需 <5(4.57.6 验证可用)。
4. 语言分支的 Match/Success/Description 由一次 generate 产出,解析依赖固定文本格式;改 max_new_tokens 只影响描述长度,不影响判定逻辑。
