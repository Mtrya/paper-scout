## 猜想(已检验,方向成立):前向预测世界模型的可辨识性缺口跟踪"像素可见性",训练时对齐头是外科手术式修补
- type: hypothesis
- keywords: JEPA, 世界模型, 可辨识性, 本体感知, 像素可见性, 对齐头, PSG-JEPA, LeWM, 逐维探针, 状态监督, 动态转移头
- status: supported(cube 单任务同种子对照复训 + 400 集逐维探针;方向一致,幅度与论文协议不同)
- confidence: high(方向)/ medium(幅度与跨任务推广)
- scope: 动作条件 JEPA 世界模型(LeWM 系);OGBench cube 直接验证,LIBERO/真机未复核
- source: runs/2026-08-16-omega0-psgjepa/psgjepa-2608.06799/

### 动机
PSG-JEPA 论文报了"EE-yaw 读不出(r=0.08)"但只给分组均值,没追机制:缺口究竟是"表示没对齐"还是"前向预测根本没有动力编码像素里看不见的东西"。我们猜是后者,且预测对齐收益应跟踪"数据里有变化但像素里看不见"的维度。

### 支持证据
- baseline(LeWM,λ_g=0)逐维可辨识性与像素可见性(|Δobs| 与像素帧差的相关)跨维相关 0.42——前向预测确实只编码像素里看得见的东西。
- 缺口高度集中且被精确补上:腕部偏航(dim 5,方差全场最大、可见性 0.053)r 0.03→0.76;末端姿态(dim 15/16)0.21/-0.23→0.79/0.75;已满分维度仅 +0.01。
- 两对齐头分工明确:关节速度维(单帧像素原理上不可见)baseline ≤0.20,PSG 后 0.73-0.91——动态转移头(监督多视野 Δq)直接注入速度信息。
- 未监督的 privileged 维(19-27)PSG 后原地不动(≤0.25)——对齐是外科手术,不是泛泛表示变好;这也是内部对照,排除了"加任何辅助损失都会涨"的解释。
- 长程 rollout 改善复现:15 步 MSE 1.48 vs 1.72,30 步 1.65 vs 1.90;5 步持平(baseline 略优 0.46 vs 0.51)。

### 反对证据/边界
- corr(vis, Δr)=-0.11:提升幅度本身不直接跟踪可见性——低可见性是必要条件而非充分预测器(还需维度在数据里真有方差;dim 4 方差 7e-8 基本不动,两模型都读不出)。
- 与论文绝对数值不可比(协议不同:按集留出、frameskip=5、线性探针 vs 论文 MLP);cube 单任务,未复核 Q2 规划/Q3 策略层。

### 当前判断
设计潜空间世界模型时,"这个状态维度在像素里可预测吗"应成为表示诊断的第一问;训练时监督(用完即弃的对齐头)是低成本答案,且静态/动态头可以按目标维度(位置/速度)分别设计。与 Marionette 的阴性结果(软惩罚塑物理可行性失败)对读:软损失适合塑形"表示里有什么"(优化问题),硬可行性约束必须外置(记账问题)。

### 下一项判别性实验
在 LIBERO 级任务上复核"对齐改善规划"是否同样跟踪像素可见性缺口;或构造"同一维度可控地增/减像素可见性"的数据对(如遮挡腕部标记),直接操纵自变量。

## 猜想(部分检验):agent 经验沉淀成 harness 可行但有明确边界——不跨任务族
- type: hypothesis

- status: open(文献因果证据 + 我们 robocasa 线的早期观察一致;自有 harness 尚未建成)
- confidence: medium-high(文献 756 轨迹受控实验;我们侧只有定性观察)
- scope: 长程 AI 研发/轨迹产出任务;以 sim 成功/失败为验证器的数据工厂场景
- source: runs/2026-08-16-omega0-psgjepa/(报告 AIRD 线程);另见 libero/robocasa 实验 session 观察

### 动机
我们的数据工厂路线依赖"强 agent 磨出的经验沉淀成 harness,弱模型也能快速产出轨迹"。AIRD(Beyond Final Scores)恰好对经验复用与 harness 演化各做了因果实验。

### 支持证据
- 经验复用对弱模型收益最大(任务内:LongCat +0.145 vs Opus +0.036;任务间 lessons:最弱的 DeepSeek +0.093 且零分 rollout 13/57→0,最强的 Opus +0.001)。
- 显式提炼的 lessons 优于直接访问原始工作区(过滤噪声本身有价值);自己提炼优于跨模型互换(兼容性取决于接收者)。
- 自动 harness 演化(Opus-4.8 外层优化 preamble/规则/hooks,4 轮)种子任务 +0.12、同族 +0.06、跨模型 +0.03。

### 反对证据/边界
- harness 收益**跨任务族为零**(系统优化任务上演化的规则对 CUDA/模型开发无效)——harness 大概率要按任务族/仿真器分别沉淀。
- agent 偏离标准解法时,钻评测空子的概率(6.3%)五倍于真创新(1.2%)——验证器必须 cheap 且难钻(sim 物理真实性是隐性优势)。

### 当前判断
数据工厂按任务族分别沉淀 harness;验证器保持物理真实性;先用 C1(定题)/C2(执行)/C3(反馈控制)分解量化自己 agent 的瓶颈再决定优化哪里。

### 下一项判别性实验
robocasa 第二/三任务上实测:harness(含第一任务沉淀的 GDM 区域经验)能把弱模型的产出成本降多少;跨任务(换 GDM 区域形态)后保留多少。

- outcome: working

- invalidated-by: 平台提供更完整的预装镜像或修复日志流
- source: runs/2026-08-16-omega0-psgjepa/psgjepa-2608.06799/(README + train_psg_job.sh);INSPIRE.md "2026-08-16,GPU Job 落地"

### 目标与背景
PSG-JEPA 10 epoch 复训约 9.5h,超 notebook 24h 上限边际且占交互实例,转 GPU Job。四次失败各修一坑,最终全链路打通。

### 实际执行
1. **镜像**:job 只认 registry URL 且 host 必须 `docker.sii.shaipower.online`;平台目录里给的 `docker-t.sii...` 前缀过不了校验,直接改写后多数镜像 NotFound(卡 creating 十几小时无报错)。唯一实测可拉:`docker.sii.shaipower.online/infly-dev/sandbox-base:ubuntu24.04-py3.12-1.0.0`(裸镜像,无 torch)。
2. **venv 密封**:notebook 侧 venv 原是 `--system-site-packages`,到裸镜像里缺 torch。改 `pyvenv.cfg` 为 `include-system-site-packages = false`,把 torch 2.7.0+cu128/torchvision 0.22.0+cu128/einops/pandas/matplotlib/httpx/scikit-learn/opt-einsum/h11 全部装进 venv;pip 用 ensurepip 恢复。密封后 venv 在 GPFS 上 notebook 与 job 双端可用。
3. **shm**:job 必须 `--shm-size 64`(默认 shm=0,DataLoader 直接 bus error)。
4. **日志停更假象**:训练中 `inspire job logs` 从某时刻起完全停更(停 3 小时+),但 job 健康、ckpt 按小时落盘。**判活以 GPFS ckpt 时间戳为准,勿凭日志判死**;最终 ckpt 与 SIGUSR1 清理同时刻写入,job 正常 succeeded。
5. **同名 job 重复创建不报错**,改名要加后缀;job 查看用 `inspire job status/logs <name> --workspace 分布式训练空间`。
6. **OGBench cube h5 是 flat 结构**(ep_len/ep_offset 切集),pixels 列必须 `import hdf5plugin` 才能解码;动作编码器输入是 frameskip×action_dim=25 维展平块(train.py `effective_act_dim`),探针喂原始 5 维会报 conv1d 通道错。
7. **守候脚本模式**:notebook 上轮询 ckpt 落盘+尺寸稳定(两次 stat 间隔 90s)后自动启动探针,训练/探针零人工接力。

### 观察结果
四次失败后第五次 job 一次跑通 10 epoch;notebook 冒烟(limit 3 step)+ 后台探针(400 集)全部稳定。

### 可复用做法
train_psg_job.sh(set -ex + preflight + 大数据集拷 /tmp)是 job 入口模板;wait_and_probe.sh(轮询 ckpt+自动接力)是长训练后处理的模板;venv 密封流程对任何"notebook 调试→job 训练"迁移通用。

### 失败信号与恢复
job 长期卡 creating → 镜像名不存在(换 sandbox-base);DataLoader bus error → 加 --shm-size;conv1d 通道错 → 检查 frameskip 展平;日志停更 → 看 ckpt 时间戳而非日志;notebook 被回收 → venv/ckpt 在 GPFS,/tmp 的 h5 重拷 2 分钟即可续跑。
