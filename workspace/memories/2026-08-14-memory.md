### 动机
08-13 把监督信号的问题钉在清晰度轴上(真值派生 > 构造信号 > 一致性 > 噪声代理)。本轮三篇论文(RIFT、ForeWAM、模拟器坍缩)从三个方向指出第二条正交的轴:信号是否保持分布形态。点估计(条件均值、一致性、模拟器的 mode)会退化梯度;分布保持(FM、口头化分布、共同训练移动目标)把学习留在信息区间。

### 支持证据
- RIFT:条件 FM 监督 anticipation token(对未来潜斑块的分布做速度场监督)vs L2 回归单点未来;论文测得只差 0.4 点(LIBERO 单峰数据),但设计动机明确——L2 的条件均值在多模未来下会把有效策略平均掉。我们的玩具重建在双模任务(直搬/绕行)上检验这一差异(见线程包)。
- ForeWAM:未来槽纯噪声、σ=1 单趟 prefill——缓存的正是"去噪网络第一步的内部状态",编码未来分布而非某个采样。
- 模拟器坍缩(2608.12253):坍缩的模拟器杀掉奖励方差的模拟器侧对比(式 6 方差分解);修复=口头化分布采样(恢复 RLHF 前 reference 分布)+ 共同训练(移动靶点)+ 模拟器奖励的 SPICE 式方差课程(目标 σ²≈0.25)——对抗/合作奖励都会让模拟器重新坍缩。
- 08-13 的 U-OPSD 结果作为反面:一致性(点估计)只能锐化已有分布,失明侧一字不动。

### 反对证据
暂无直接反对;但"清晰度轴"上无真值但分布保持的信号(口头化分布)仍可能携带错误——两条轴独立,分布保持不保证正确性,只是不退化。

### 当前判断
设计自训练循环时问两个问题:信号携带正确性吗(清晰度轴);信号保持分布吗(形状轴)。坍缩的外部锚(单模拟器、一致性、条件均值)提供的梯度指向它自己的尖峰。

### 下一项判别性实验
双模合成任务上直接对照 L2 条件均值 vs FM 的学出行为(本轮玩具已搭好,rift-l2 vs rift-fm 变体;若差异小,加大模间距离与模权重不对称性重测)。

### 目标与背景
RIFT 未放代码,其核心主张(掩码未来读→崩、终态干净缓存重放→恢复)是可移植的因果协议。在启智 4090 上以 64×64 合成双连杆臂搬运(双策略模式=直搬/高弧绕行,让"给定观测的未来"天然双模)+ 联合视频/动作流匹配模型重建,并加一个计划注入探针(指令 A + 注入 B 的未来缓存,看动作跟谁走)。最终架构(v3):视频分支 3D-UNet 对 [观测帧|8 帧未来] 流匹配,瓶颈特征图逐位置投影成 K/V 作未来缓存;动作分支 16 token × 4 层 transformer 每层交叉注意力读缓存。五个变体:joint(rollout)/currentonly/rift-l2/rift-fm/noiseslots(ForeWAM 式 σ=1 噪声槽)。

### 实际执行
- 关键前提:视频 token 不 attend 动作 token,未来缓存才动作无关、可记录-编辑-重放;配对试验用同 seed + 同 ε_a0 + 同 σ 调度。
- 干预实现:掩码=交叉注意力清零(不是 K=0!);空间乱序=瓶颈帧内位置换位;时间交换=瓶颈帧间换位;终态重放=最后去噪步缓存固定复用;瓶颈时间维是 ceil(ceil(9/2)/2)=3(两段 stride-2 下采样),干预的"帧"要按 3 分而不是 8。
- 计划注入只换未来侧瓶颈位置(第 0 帧=观测侧保留 A,帧 1-2=未来侧注入 B),否则指令 token 也被替换、混杂"指令注入"。
- 训练:滑窗采样(任意中间帧作观测+8 帧未来+16 步动作块),闭环第二块起喂中途状态(第一版只训静止首帧、闭环观测 OOD 全灭);视频流损失只算未来帧。
- 两次架构级教训:玩具尺度 DiT 生成 8 帧 64×64 流匹配学不动(loss 平台 0.64),3D-UNet 同尺度 ~0.04;奇数时间维(9 帧)经 stride-2 上采样尺寸超一帧,要裁剪对齐。
- E(anticipation 未来帧)以 detach 状态存 checkpoint,加载后是 CPU 张量,eval 前必须 .to(dev)——本机 CPU 冒烟发现不了这种设备 bug,远端首跑才暴露。

### 观察结果
joint 80 任务 26.2%;四项破坏干预(mask/noise/shuffle/swap)全 0% + ADE 7.0-7.6px,冻结当前 0%/1.1px,终态重放 11.2%/3.4px(方向同论文、恢复不完整);生产者 0-7.5%(noiseslots 7.5% > learned token 0%,呼应"未来槽不用学"),延迟 29.5-30ms vs rollout 51.6ms;计划探针 60 对:跟随注入比例 0.0%、注入成功率 33.3% > 原版 26.2%——动作读缓存的动力学值,不读计划身份。

### 可复用做法
static/shuffle/motion 三元组(08-13)+ 本轮 mask/shuffle/swap/finalclean 四干预 + 计划注入,构成"未来读"类论文的玩具级标准检验包;单文件探针 + 远端 --eval-only 重跑模式(训练与评估同脚本、评估幂等可单独重跑)便于迭代修复。

### 失败信号与恢复
本机无 GPU 且 MinerU OOM(15G 内存 + swap 满)——远端路由、解析放弃缓存改读 HTML;4090-2 组驱动 12.8 vs 旧 venv torch 2.13 的 CUDA 不可用——建 --system-site-packages venv 继承系统 torch 2.7(细节见 INSPIRE.md)。

### 边界
玩具尺度结论是机制级的,不承诺数值级;干预中的噪声/冻结当前是 OOD 编辑,只作对照。

### 实际执行
47GB 卡上 Qwen3-4B(策略+模拟器两份 bf16 16GB)+ LoRA r=32 + G=4×5 轮对话的 REINFORCE,连 OOM 三次后定位四个坑:
1. transformers 5.4 的 from_pretrained 弃用 torch_dtype,必须用 dtype=torch.bfloat16——旧参数被忽略时 4B 以 fp32 加载,两份即 32GB,直接爆。
2. token 级 NLL 的图累积:5 轮 × 多条轨迹的前向图全留着一次 backward,激活线性于 seq 长(2048 tokens 时单条前反传 ~31GB)。逐轮(甚至逐条)前向后立即加权 backward 释放。
3. 长上下文本身:NLL 每轮条件上下文从全历史(5 轮 ~4000 tokens)改为最近 1 轮(~1200),REINFORCE 的 token 级权重对长程条件不敏感;否则 2048 tokens 激活就 ~46GB。
4. 左 padding 的多条批量 generate 会退到 eager attention 物化完整 scores,batch 降到 2。
配套:引擎直接包 live 的 peft 模型(推理用最新权重,hf 后端无需 merge_and_unload),省掉引擎+驱动的重复权重;PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True 减碎片。

### 观察结果
4B + G4 + 5 轮,单步 280-440s(生成 ~13k tokens + 20 次逐条 NLL 前反传),GPU 利用率 ~47%,瓶颈在 CPU 侧 decode 循环;vs 变体的"口头化分布"生成(max_new_tokens)是最慢项,600→250 后步耗时减半。结果:single distinct2 0.407→0.378、cot 0.415→0.318(self-BLEU2 0.132→0.166)——坍缩签名 20 步内可见;vs distinct2 0.435→0.517、self-BLEU2 0.121→0.096——口头化保多样性方向复现。

### 边界
单卡 20 步 × G4 是玩具尺度;reward 未收敛,面板 n=4 噪声大;cot 修复效果在本尺度未见,须更大预算重测。
