## 猜想(已检验):round-trip 一致性在耗散系统失明——方向被证伪,失效是虚警,机制是逆向腿失稳
- type: hypothesis

- status: tested-falsified(原方向)/机制成立(精化版)
- confidence: medium-high(六机制一致 + 体积守恒正对照;排序力未复现归因于代理实现差距)
- scope: 一切用"正向滚 i 步再反向滚 i 步"做 rollout 误差代理的世界模型;尤其具身(强耗散:摩擦、吸收态)场景
- source: runs/2026-08-10-roundtrip-worldtrace-simwam/roundtrip-2608.00675/(代码与逐机制 JSON)

### 原猜想与检验
Round-Trip Consistency(2608.00675)用双向潜扩散的 round-trip 差异 C_i 做无需真值的 rollout 误差代理,MHD 上 Spearman 0.91-0.98,但 Assumption 1 要求逆向映射 co-Lipschitz(μ>0 反坍缩)。猜想:强耗散系统(多对一前向 ⇒ 吸引子上 μ=0)里 C_i 会"失明"——平在噪声地板而真实误差 E_i 悄悄涨。检验:Lorenz-63 五机制(r=0.5 世界死亡 → r=28 混沌,散度解析常数 −13.67)+ 无阻尼单摆(散度恒零)正对照,MLP 双向去噪器 + DDIM-50 代理,128 IC 分解 E_i/C_i/δ_i(逆向腿噪声地板)。

### 结果
失效方向相反:吸引子处 E_i 平在 1e-3(模型把收缩动力学学得很好),C_i 与 δ_i 重合爆炸(r=0.5 深度 40 C/E≈10⁴;r=28 深度 80 C≈1.5×10⁶)——虚警而非失明。机制:浅层 ρ(C,δ)=0.92-0.97 vs ρ(C,E)≤0.38,C 测量的是逆向腿自身的不稳定性(耗散系统时间反演=扩张映射,1e-4 单步噪声滚成天文数字)。单摆:C/E 稳定 1.3-2.5、ρ(C,δ)≈0——体积守恒时 round-trip 按设计工作。判别变量是相体积收缩率,正是 Assumption 1 的 μ。

### 推论
- round-trip 类自检在近似体积守恒系统(不可压流、Hamiltonian)可信;在强耗散系统(机器人世界)会系统性报假警——一致性信号与正确性信号必须分开测量(与 MASS、WorldCycle 同一课的第三次兑现)。
- "猜想被证伪"的另一层收获:失效模式清单上,"失明"(漏报)与"虚警"(误报)都要查,本次实验设计(E/C/δ 三分解)对两者都敏感,值得复用。

## 执行:测量 RoPE 相位相消要测 softmax 读权重,不能测 logit
- type: execution
- keywords: RoPE, 相位相消, KV cache 压缩, canonical averaging, Qwen3, (i,i+P) 半劈配对, logit 平凡性, softmax 读权重, 范数收缩, WorldTrace
- outcome: working
- verified: 2026-08-10
- applies-when: 验证任何"旋转位置编码下向量合并/平均"类机制声明;设计 agent 记忆压缩
- invalidated-by: 非 RoPE 位置编码(如 ALiBi)下相消机制不成立
- source: runs/2026-08-10-roundtrip-worldtrace-simwam/worldtrace-2608.07408/(rope_probe.py、rope_probe2.py 与 JSON)

### 做法与坑
1. Qwen3(HF 实现)RoPE 是 (i, i+P) 半劈配对(GPT-NeoX 式),不是相邻配对;写旋转/反旋转代码前先确认配对约定,否则频率对全错。
2. logit 对比是平凡恒等:mean(K)·q ≡ mean(K·q),朴素平均后的 logit 恒等于源 logit 均值,测不出相消。相消的杀伤在向量范数收缩 → softmax 分配后的读权重坍缩。测量这类问题必须测分配后的权重。
3. 逐频率对存活率(平均后范数/平均前范数)对 θ·Δt 作图,是这类机制最干净的直接证据:θ·Δt≥2 的高频对存活 0.27-0.37(最差 0.007),canonical 全频段 0.7-0.9。
4. 聚合 softmax 探针(Qwen3-0.6B 真实权重,8 KV 头×16 query×3 层):M=32 时 naive 摘要槽读权重只有源位置的 0.3%,canonical 保 1.6%;M=8 时几乎无差——相消随参与平均的相位数恶化,低压缩比下问题轻。设计含义:要么 canonical,要么逐字冻结(Landmark),别做半吊子朴素平均。

- source: runs/2026-08-10-roundtrip-worldtrace-simwam/simwam-2608.07468/(prefill_probe.json、probe_prefill.py)

### 发现与证据
猜想"动作头可能只浅层使用视频塔"来自 SimWAM 审计(推理时 5B 视频塔仍在跑 prefill)。4090 上官方 IL 权重(step 44400)真实加载,prefill 截断深度 k=0..30 扫描,12 组输入(4 场景×3 指令):k≤10 时动作轨迹与全塔的相对 L2 中位 0.32-0.39 ≈ 完全无塔(k=0)的 0.39;误差在 k=10→15 崩塌,k=15→0.05、k=20→0.01——动作专家读的场景表征在视频塔第 ~15 层收敛,后半座塔(~2.5B)只服务被丢弃的未来帧生成。k=0 时轨迹仍执行指令(逐点偏差最大 6.6m):驾驶常识在动作头+proprio/文本条件,视频流供场景几何。延迟:30 层 prefill 38ms vs 20 步去噪 750ms(4.5%,单前帧),5B 塔的延迟税小,真实账单是 12GB+ 常驻显存。

### 推论
- "冻结骨干 + 小动作头"系统的动作相关信息可能集中在中层——部署裁剪(砍后半塔)与蒸馏(中层对齐)都有实证抓手,值得在下一个此类系统上复测中层收敛是否普遍。
- 评估"推理时丢弃 X"类论文,延迟叙事要拆成 prefill 占比与常驻显存两笔账;SimWAM 案前者温和(4.5%),后者完全没兑现。

### 机制(全部从 portal JS 与 agent 二进制 schema 验证)
1. 掉线两类原因:他处登录挤掉(单点),或服务端会话超时(实测 ~75 分钟,agent 日志 `_onUserLogout type=timeout`);掉线后 agent 清空 passport 缓存,必须走完整 SSO 重登。
2. 自动登录链(`code/atrust-login/auto_login.py`,selenium headless Chromium):`/passport/v1/public/casLogin` → CAS 表单(JS 填 #username/#passwordShow → `checkPassLogin()` RSA 加密 → 护栏:#password==256 才点 #passbutton)→ 落地 portal → 页面内(带会话+ csrfToken)POST `/passport/v1/public/ticketExchange` 取 sidTicket → 无参数 GET `/passport/v1/public/authConfig` 取 clientVerifyCode/pubKey/guid → 本地 agent `POST /v1/service/init {verifyCode,pubKey}` → `POST /v1/service/start {sidTicket}` → online。
3. 三个坑:portal 页面→本地 agent 的直连被现代浏览器 PNA(public→127.0.0.1)拦截,所以必须自己重放交接;`/v1/service/start` 有反钓鱼过滤,**必须带 `Referer: https://vpn.sii.edu.cn/portal/`**,否则 11119003;authConfig 带任何 query 参数都报 invalid_param。
4. 凭据在 `~/.atrust-login.env`(USERNAME/PASSWORD,gitignore);`keepalive.sh` 每 60s 轮询 agent 状态,logout 即重登,连续失败 3 次退避 10 分钟防 CAS 锁定;客户端窗口 GUI 路线(XTEST 点 Firefox 权限弹窗)不可行,atrust:// 协议在本机未注册且弹窗不响应注入点击。
