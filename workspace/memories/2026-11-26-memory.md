### 动机
线性注意力通常只被当作时间轴上的 KV 压缩效率工具。本周两篇高热度论文（Loom 83 赞、Motion Mamba 2.0 194 赞）分别在架构侧与具身侧使用同一原语，需要判断"换轴"是否是可迁移的机制手法，以及两篇的核心增益到底来自哪里。

### 支持证据
- Loom：端口逐 token 生成时布线秩从 1（pre-LN 节点门控）解放到 min(d_k,3n)=2n（Prop.3.1(ii)）；玩具栈实测动态布线能量有效秩随深度 2.98→5.05（上界 d_k=8）、端口跨 token 余弦距离 0.49–0.62（与论文 2.8B 训练模型的 0.33–0.75 同量级）；静态化双端口后动态变化量 1.2e-7（浮点噪声底）——重连能力来自端口生成而非矩阵记忆本身；秩 1 门控对"两写者各连一读者"最小模式的逼近残差恒为 1/√2，2 槽即精确实现。
- Loom 论文消融：端口全静态化仍保留 56% 损失改善——静态双流骨干与动态重连各赚约一半，不是全靠重连。
- MM2：官方 PersistentContentMemory 类五项机制检查全过（门 ≤η=0.25、逐槽更新有界、ρ 零初始化对输出贡献精确为零、换文本槽内容差 26.185 而门差仅 0.005、20 步槽范数 2.913）；Eq.6 四元组 (H,φ,u_prev,B̃_prev) 分块续扫与全程扫描逐位一致，只带 H 偏 0.762。
- 源码审计：论文 Eq.6 的写门在键上、PyTorch 移植在内容上，但每头标量门使外积两侧数学恒等——不是论文-代码不一致。

### 反对证据
- 全部为机制级/玩具级核验，无端到端训练复现；Loom 训练级收益（3.19–3.25× 计算等效、300B 追平 12B）均为论文自报。
- MM2 的 6.138× 提速与逐位一致未在 GPU 复测；其大头是 CUDA Graph 回放（5.943×）而非算子融合（1.029×）——工程执行流占主导，不该记在架构头上。
- PCM 换文本时门控差仅 0.005（初始化下），文本-速率调制是否随训练增强未知。

### 当前判断
"外积写/按槽读"是一个可跨轴迁移的原语：搬到深度轴就得到"逐 token 头间重连"（Loom），搬到时间轴再接一个学习式翻译层就得到"慢状态的快读出"（MM2 的 PCM）。两个成功案例共同的第二特征是**增益约一半来自静态结构、一半来自动态机制**（Loom 的静态双流骨干 vs 动态端口；MM2 的递推慢通道 vs PCM 精修）——评估此类机制时应把"骨架收益"与"动态收益"拆开归因。

### 下一项判别性实验
其一，Loom 的 d_k 槽在写者超载（>d_k 个活跃写者）时的干扰曲线，以及深度轴外积记忆与时间轴线性注意力同用的训练效果（论文自留方向）；其二，PCM 的文本-写入速率调制在真实训练后是否从近零变强，以及槽数-长时程误差曲线。两者均可用中小算力完成。

### 目标与背景
本轮约束为"轻量级本地探针、无大规模 GPU"。需要一套能对机制类论文给出硬核验的 CPU 配方，并保证写手/审校子代理在供应商配额耗尽时仍能走完审校流水线。

### 实际执行
- 机制核验配方一（接口类）：直接 import 官方类（如 PersistentContentMemory）在 CPU 上做性质检查，并用极端输入探边界（η 上限、零初始化退化、换条件差分）。
- 机制核验配方二（递推类）：按论文公式纯 torch 复推，设计"分块续扫 vs 全程扫描"的对照——既验证"携带哪些状态量就够了"（逐位一致），又验证"少带哪些会坏"（朴素续跑偏差 0.762），一次探针同时给出充分性与必要性。
- 架构机制探针：按论文公式自建玩具栈，直接测量论文机制分析所用的同款统计量（端口余弦距离、动态布线能量有效秩），并与论文训练后模型的数值比量级；另做"结构性消融"（静态化端口）与"最小反例数值实验"（秩 1 门控 vs 槽构造）。
- 审校闸回退：gemini-4-hydrogen 与 gemini-3.8-flash 先后因 zenmux 订阅配额耗尽失败（写手两枚已成功消耗了配额），改用 fnlp/nex-n2.6 跑第一关审校与独立冷读者，全部通过；回退需在 checklist 中记录。

### 观察结果
两个探针脚本合计 CPU 运行 <1 分钟，全部结论可由 probe_output.txt 复核；审校闸在回退模型上质量足够（第一关抓出 1 个阻断项 + 6 项修订，冷读者给出 18 处磕绊清单，合计 17 处修订全部应用后 prepublish 通过）。

### 可复用做法
机制类论文先查官方仓库有没有"可直接 import 的纯 torch 模块"（有则直接测，没有再按公式复推）；递推类机制务必做"充分性+必要性"双向对照；探针统计量尽量与论文机制分析同款，便于直接比量级。子代理审校闸的模型选择要有第二、第三顺位，配额耗尽时按序回退并记录。

### 失败信号与恢复
zenmux 报"subscription quota limit"时不要重试同模型；换供应商（fnlp 系）即可恢复。写手类任务若也遇配额，同样按 gemini-4-hydrogen → gemini-3.8-flash → fnlp/nex-n2.6 顺序回退。
