### 动机

### 支持证据
- balance 5/5:零稀疏推挡尝试,全部直接合成 PD 控制器上传(增益同族异参 θ45-70、θ:ω≈4:1,与数值 LQR 结构一致);手写 LQR 被 numpy 缺失挡住后改手调,杆长参数错 2× 仍镇定(反馈吸收模型误差)。
- balpush(禁 upload_controller)3/3:agent 先做 1 次试探推,再写内联 Python 循环包住桥命令(state→f=clip(40θ+9ω+1.5x+3v)→push),终态 θ=-0.0001rad;决策延迟按调用计费不问决策者,于是 agent 把自己从回路里摊销掉。
- 全部 6 任务 26/26;单 trial ~16k token、<1 分钟(AGP 论文单任务 $9-24、20-50 分钟)。

### 反对证据
- 沙盒是 2D、单自由度、全可观状态;真实机器人(接触、形变、多自由度耦合)可能完全不同。
- 3-5 trial/任务的样本量小;同一模型不同日的行为方差未测。

### 当前判断
"小脑由下行内容现场合成"在前沿 coding agent 上已是默认行为而非特例;接口设计的自由度不在"要不要小脑",而在"让它住在哪一层、以什么协议汇报"。对 benchmark 路线的启示:单未知量系统辨识与单自由度闭环已不足以难住这个量级,难度要放在多未知量耦合、长 horizon 部分可观、边动边学。

### 要点
- **inspire CLI 绝不能带 https_proxy 走 mihomo**(qz.sii.edu.cn 必须直连 aTrust utun7):报 TLS socket disconnected / "Cannot determine the current platform account" 时先 unset 代理再试;mihomo-atrust 技能有完整架构。
- 实例内 uv/pip 要显式设镜像:`UV_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple`(默认 PyPI 直连极慢,5.3G 卡 2 小时级;换源后 ~4min/G)。

- uv sync 在网络存储(qb-ilm2)上安装阶段 I/O 极慢(小文件 unpack,6.7% CPU),是正常现象不是卡死;看 /proc/<pid>/fd 的最新目标文件判断进度。
- GPU 空闲自动停机(2h 警告+1h 宽限)只盯 GPU 利用率,下载期 0% 照停;环境链全部幂等可重放是唯一的保险。
- codex CLI:`codex exec -s workspace-write "<prompt>"`(模型 gpt-6-astra);codex.log 只记 exec+总结(reasoning summaries: none),行为分析要靠 trace 数字反推;沙盒无 numpy 会改变 agent 的策略选择(手写 LQR→手调 PD)。

## 执行经验:SyncWorld 启智环境链(本轮踩坑全集)
- type: execution
- keywords: inspire, uv.lock, pypi 镜像, hf download, 空闲停机, cancel-save-image, HF_HOME, episode 选择
- source: runs/2026-09-16-agp-syncworld-kdn/syncworld-2609.09155/

### 要点
- **uv.lock 钉死的 URL 绕过索引镜像**:`--frozen` 时锁里的 files.pythonhosted.org 直连极不稳(400MB 的 nvidia 包反复下载-校验失败-重下,缓存不增反减)。解法:`sed -i 's|https://files.pythonhosted.org/packages|https://pypi.tuna.tsinghua.edu.cn/packages|g' uv.lock`——tuna 镜像同路径同字节,hash 校验照样过,6541 条 URL 改写后 0.6MB/s→9.7MB/s。
- **uv 在网络存储(qb-ilm2)上 unpack 0.6MB/s 是写瓶颈**:把 UV_CACHE_DIR 与 venv 都放实例本地盘(/root),先从网络 cache `cp -a` 回灌(11G 读只要 2 分钟,读快写慢)。
- **GPU 空闲停机再教育**:长下载期 GPU 0% 必触发(本轮 01:22 创建 04:29 被停);stop 时的 save-image(65G overlay)会 COMMITTING 近 1 小时且大概率失败,`inspire notebook cancel-save-image` 可中止,但 **/root 全丢**。教训:HF_HOME 放网络存储(下载一次终身复用),环境重建写成幂等脚本(rebuild_env.sh,锁文件已 tuna 化,15 分钟可重建)。
- **dl 脚本的 .done 标记不可靠**(xargs 失败也 touch):以实际文件大小为准——本轮 model-00003-of-00007.safetensors 只有 1.4G/4.9G,模型加载报裸 FileNotFoundError(hydra 吞文件名,要看 "direct cause" 链上方)。
- **checkpoint_db 用 `uvx hf download` 拉 VFM 主干**:uvx 不在 PATH 会报同样的裸 FileNotFoundError;run 脚本要 export PATH=$WR/bin:$PATH。Cosmos3-Nano 主干(~33G)不在发布 checkpoint(31.5G)里,运行时另拉。
- **eval 输出全缓冲**:整个 episode rollout 完才写 mp4/CSV,监控只能看 GPU 利用率+py-spy dump(能精确到 unipc 采样器/VAE 解码),看输出文件数会误判为卡死。
- **eval 集前 N 集常同任务**:选探针 episode 前先扫全集 DoF 画像(本集 50 集 rot/trans 比 0.53–4.24),用补丁加 --episode-indices 选强对比对(输出 episode_k 是过滤后位置,分析时要映射回全局序号)。
- 单 4090 实测速度:论文口径(35 步/CFG 5.0)一集 ~43 分钟;快速预设(20 步/CFG 1.0)约 3.4 倍速。复现质量 PSNR 27.8/SSIM 0.95(272 帧闭环无累积漂移,接触段相位性下探后回锚)。

## 证伪:SyncWorld 标定前缀的收益不按逐自由度协议分解(协议结构在发布权重上名存实亡)
- type: hypothesis
- keywords: SyncWorld, 世界模型, 标定 episode, in-context, 可观性, 逐自由度, 证伪, 上下文协议
- status: falsified(在发布权重、本灵敏度下)
- confidence: medium(2 集×2 视角×单 rollout,快速采样预设;±0.2dB 在种子噪声内)
- scope: 发布权重 yyuncong/SyncWorld(与论文四点差异:主干/单位/注意力/标定 12→6 槽),LIBERO evaluation_libero,单 4090
- source: runs/2026-09-16-agp-syncworld-kdn/syncworld-2609.09155/

### 动机
8 月 EKF 标定线的老发现:可观性按自由度逐个成立,没被激励的自由度不可估。SyncWorld 标定也按自由度组织(6 槽 x/y/z/yaw/pitch/roll),于是预测:抹掉旋转三槽后,模拟质量退化应选择性出现在转动主导的 episode 上——这是"标定 episode 真的编码了逐自由度映射"的因果检验。

### 结果(2026-09-16)
- 复现:发布权重首跑,272 帧 PSNR 27.78/SSIM 0.954/LPIPS 0.022,逐段 23.8–31.3 无单调衰减;两次下探(144–160、208–240 帧)都落在接近/抓放摩卡壶的接触相位,208–240 帧生成轨迹与真迹语义分歧(壶没放上灶台)而指标回锚——视频质量指标对语义失败钝感。
- 探针:50 集 DoF 画像(转动/平移比 0.53–4.24),选 ep14 开抽屉(4.24×)与 ep26 捡字母汤(0.53×),三条件×双视角,快速采样。抹旋转三槽在两集都与完整标定无差(27.4 vs 27.5、29.6 vs 29.4,±0.1dB 符号翻转);全零标定在全部四组 episode×视角一致变差(-0.35~-0.93dB)。段级相关 4 组仅 1 组 -0.56,其余≈0 且符号跨视角不稳。
- 结论:标定收益真实存在(有标定>无标定),但不按论文宣称的逐自由度协议分解——"有标定"是一个比特,协议结构名存实亡。与 09-14 审计发现发布版 12→6 槽互洽:发布权重里的上下文协议可能本就已弱化。

### 对主线的含义
"上下文即接口"通道确实传信息,但协议结构不可依赖——把 setup 知识托付给上下文时,指望它按设计好的槽位语义工作,目前无证据。后续若再评 in-context setup 适配类工作(如 Programmable WM 2609.10540),槽位级因果探针(--calib-drop-slots 模式)是现成的检验工具。
