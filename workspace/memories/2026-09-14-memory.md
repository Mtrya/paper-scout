### 动机

### 支持证据

- A2 五条件对照(0.6B 学生 × 1.7B 教师,自研轻量 PG 环):教师优势 |A| 是固定负优势的约 20 倍量级(2.18–3.54 vs 0.10,均为全部 token 平均),而 opd 与 fixed-neg 的长度/熵轨迹几乎重合;单 query 条件的信号衰减更快(|A| 2.00→0.96,熵 1.32→0.92)。
- A3 发布权重(1.7B)上独立复现增益:AIME24 pass@4 20.0→40.0、avg@4 10.0→24.2(30 题 × 4 条、官方 grader)。

- 没有直接反驳;但 OPSA 的判据(熵)是归纳偏置而非正确性;论文自报 OOD 增益小(MBPP+ +1.2、GPQA +4.48);A2 精度层无法判决(见下一条)。

### 当前判断

### 支持证据

### 反对证据

### 当前判断
报告任何长 CoT 模型的 avg@k / pass@k 时必须同时给出生成长度预算与自然结束率;小预算下的 avg@k 只是下界。OPSA 这类"熵自适应压制"方法的增益与长度增长耦合,评测预算成为结论的一部分。

## 执行:批量解码的长度与截断统计是批次级的,不是单条级的
- type: execution
- keywords: 批量生成, batch generate, padding, pad_token_id, eos, 长度统计, 截断率, 左填充, 响应切片
- outcome: working
- verified: 2026-09-14
- applies-when: 用 HF `model.generate` 对同一 prompt 采 k 条并统计长度/截断率时
- invalidated-by: 换用 vLLM/SGLang 等按序列返回真实长度的推理栈
- source: runs/2026-09-14-opsa-pawbench-syncworld/opd-deconstruction/

### 目标与背景
用"撞上限率"判断长 CoT 模型的评测预算是否够用。

### 实际执行
同一个 prompt 采 k 条时批量解码(比逐条快约一个数量级),再统计每条的长度。

### 观察结果
HF 批量解码把较短序列 padding 到批次内最长序列的长度(常见配置下 pad id = eos id),因此 `row[len(prompt):]` 得到的是批次最大长度,不是该条的真实长度;同理"撞上限"是题级事件,不是单条事件。

### 可复用做法
要么按批次汇报(题级截断率 + 批次自然结束率),要么在解码后按 EOS 位置逐条截断再统计;要保留单条长度就得存 token id 或文本。

### 失败信号与恢复
误把批次长度当单条长度会把截断率高估、把"自然结束的样本"说小;发现后按批次口径重述或重跑(存文本)。

### 边界
只适用于 HF transformers 批量解码;左填充(`pad_left`)时响应切片还必须用填充后长度,否则响应会带上 prompt 尾部(本轮 A1/A2 曾因此重跑)。

## 执行:远程对照实验的时间预算要用"每条件实测速率"滚动重估
- type: execution
- keywords: inspire, notebook, 排队, pgrep 自匹配, setsid nohup, 共享 workroot, 窗口, 实验预算
- outcome: working
- verified: 2026-09-14
- applies-when: 在多机(启智 notebook)上排长链实验,且有硬时间窗口
- invalidated-by: 平台取消 18 小时自动停机或改用持久化训练服务
- source: 本轮三轮实验重排(自研 PG 环、A3 评测、A3 扩展)

### 目标与背景
窗口有限时把实验排完。

### 实际执行
先起一个条件量速率,再决定其余条件的样本量;把后续任务写成"等待文件出现 + 等待进程退出"的门卫脚本。

### 观察结果
- 用 `pgrep -f "condition fixed-pos"` 做门卫会匹配到门卫自己的命令行(自锁死循环),必须用 `[c]ondition` 之类的模式回避自匹配。
- 同一 GPU 上并发两个大任务(1.7B@32768 的 KV cache ≈19GB + 训练的 28GB)会 OOM:并发前先算显存,或分机。
- 用 0.6B 评测链(2.8GB)与 1.7B 长上下文评测(19GB)分机后都跑得动;跨机共享 workroot 时结果文件天然同步,不用搬运。

### 可复用做法
把"评测链 + 门卫"写成脚本放共享盘,在哪台机器上起都一样;每个条件产出 JSON 后就地增量落盘,窗口不够时可以按已完成的题数交付并如实标注。

### 失败信号与恢复
OOM 报错里会直接给出各进程占用(可据此定位是谁撑爆的);门卫自锁时用 `ps -eo pid,ppid,etime,args` 看 etime 与父子关系。

平台相关的路径、镜像与配额细节留在 `INSPIRE.md`(gitignore),不进本文件。
