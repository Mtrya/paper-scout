# 2026-07-31 巡航研究记忆

论文池 2026-07-18 ~ 07-30。深度线程:ABot-World-0(2607.19191)、UMI 数据(2607.15330 / 2607.25895)、实时策略(2607.27205 / 2607.26055)。三个真实验:一个证实、一个证伪、一个测出论文未测的维度。

## 猜想与判决

### 猜想 1:UMI 演示数据缺 recovery 行为 —— 证实(高置信)

- **启发**:HiFi-UMI 把 fidelity 推到 ~3mm,但如果演示者追求一次流畅完成,犯错-纠偏行为根本不会被采集——fidelity 再高也记录不到不存在的行为。
- **验证**:下载 HiFi-UMI-2K 全量 1,125 episodes,做运动学测量(双手方向反转次数)。先核验 action[t]==state[t+1](逐位精确相等),否则指标全错。
- **结果**:90.2% episode 零方向反转,38 个任务中位数全部为 0。recovery 覆盖需要刻意设计的犯错协议或仿真扰动增广,不会在自然采集中免费出现。
- **产物**:`runs/2026-07-31-abotworld-umi-turbovla/umi-data-scaling/code/`。

### 猜想 2:πR² staircase 的优势是模态特异的(对视觉扰动更鲁棒) —— 证伪(中置信,玩具局限)

- **启发**:staircase 的 last-minute finalization 应当更抗"观测里看不见的扰动"。
- **验证**:1D 玩具复现(sync vs staircase),注入 proprio 可见扰动与纯视觉扰动对比,5-8 seeds。
- **结果**:两种扰动下误差几乎重合——优势不是模态特异的;真正的自变量是**观测延迟档**,d 小时 staircase 付质量税,d 大时反超。玩具局限:1D、无记忆专家、不计算力价格。
- **副产品(可能比判决更值钱)**:staircase 实现空间是零文档雷区,三种自然实现全部发散(误差 2–6×):(i) rolling buffer 前槽钉 τ=1 而训练 τ~U[0,1) 不含 1,embedding 外推;(ii) 步长 1/(H−1) 时高 τ 区流场增益 1/(1−τ)≈15,欧拉迭代临界不稳定;(iii) 全 buffer 每 tick 步进 = 动作提前 12 tick 冻结 = 长开环。能工作的设计:与 sync 相同的 K 层去噪网格 + 只步进前 K 槽 + 前槽完成最后一步后立即发射。
- **产物**:`runs/2026-07-31-abotworld-umi-turbovla/realtime-policies/code/pir2_modality_toy.py`。

### 论文未测维度:ABot-World-0 长程可控性 —— 新现象(高置信,单 rollout)

- **启发**:论文只测 60s 视觉伪影,从未测长 rollout 中模型还听不听话。"无限"机制(21 latent 帧滚动窗 ~7s + 5 张参考图负 RoPE sink)天然让人怀疑 >7s 的可控性。
- **验证**:启智 4090(48GB)实跑 640-block(10.7 min)rollout,逐 block 测 yaw 指令跟随率 + 画面质量。
- **结果**:**不是衰减,是阵发性崩溃**。首尾跟随率同为 ~0.95,但 block 130-180 塌到 0.25、460-500 塌到 0.75,之后自行恢复;崩溃窗画面同步涂抹、同步恢复。滚动窗 + sink 让统计意义上无限续命,但模型会反复进入退化态再被 sink 拉回。
- **产物**:`runs/2026-07-31-abotworld-umi-turbovla/abotworld0-2607.19191/code/`。

## 核验类发现(非猜想驱动)

- ABot-World-0:动作注入是 270M 参数 conv adapter(总参数 5.1%),控制带宽 ~1.3Hz;demo 实际 12FPS vs 论文 16FPS(5090 DiT 生成速率)。
- fidelity × scale 坐标系:HiFi-UMI(保真)决定 UMI-only 能否去掉真机 anchor,Xiaomi(规模)决定 out-of-box 泛化;parity 可用 ~10× 数据买到;成本从不消失只转移。
- 实时 VLA 数字口径三问:chunk 率还是反应率(TurboVLA "32Hz" 实为 chunk 率,replan ~2.7Hz)?离线缓存模块算不算参数量("0.2B" 含不运行的 BERT,部署 ~107M)?延迟是否同口径?

## 方法论沉淀

- "长/大/快"声明应配衰减曲线,单点数字不足以评估系统声明。
- 猜想驱动与 claim 核验各占一半时产出最好。
- staircase 调试教训:先跑无扰动 trace 再谈对比;τ 网格与训练分布对齐是生死线。
