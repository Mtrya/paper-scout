# ttt-arms 线程:在线 TTT 六臂对照(ASCENT 2610.05303 × ouroboros 2610.05076)

在**真实权重、真实算力**(Qwen3-0.6B + LoRA r=16,Inspire 单卡 4090 48GB)上,把两篇同月论文的机制放进同一个在线 TTT 任务流做受控对照:六臂同一 base 独立起跑,同一任务顺序,同一更新节奏,只有"更新算子"不同。240 任务 × 6 臂全部跑完(Settlement 臂跑了两遍,见"已知偏离")。

- 锚点论文:`papers/llm-agents/ascent-2610.05303.md`、`papers/llm-agents/ttt-ouroboros-2610.05076.md`
- 预登记预测:`../assets/PREDICTIONS.md`(实验 B,B1–B5)
- 代码:`code/`(taskgen.py 任务生成/验证器、harness.py 训练骨架与各臂、probes.py 独立真实文本、run_arm.py / run_all.sh 入口、base_rate.py 难度标定、selftest.py GPU 自检、debug_gen.py 轨迹打印、analyze.py 分析与出图)
- 数据:`code/analysis/`(arms_results.jsonl 逐任务、arms_eval.jsonl 每 20 任务的验证点、arms_updates.jsonl 逐 buffer 更新日志、curves.json 滑窗曲线数据、summary.json 汇总、run1.log 六臂原始日志)

## 实验设置

**任务流**(程序化生成、程序化验证,4 族 × 60 = 240 任务串行到达,难度按相位从 L1 漂到 L3):

| 族 | 内容 | 工具协议 | 验证 |
|---|---|---|---|
| strxform | 字符串变换链(reverse/upper/lower/rot13 组合) | `apply <op>` / `show` | 末态字符串相等 |
| calc | 整数表达式求值(级别≥2 追加乘 K;级别 3 带括号) | `calc <expr>` | 数值容差 0.01 |
| world | 2–4 房间文本世界,go/take/put/inventory | 同左 | 目标物最终在目标容器 |
| listops | 列表操作链(sort/rsort/dedup/reverse/evens/odds/add k/mul k) | `listop <op> [k]` | 末态列表相等 |

统一协议:`<cmd>...</cmd>` 或 `<answer>...</answer>`;无标签、未知动词、参数不合法 → 该轮记为**非法轮**(对应 ASCENT 的 d_{i,t}=0)。每族在对话里带一段**已解出的演示 episode** 作为 few-shot(演示实例与当前任务不同,不能照抄答案)。轮预算 strxform/calc/listops/world = 6/5/6/7。难度旋钮 `TTT_LEVEL_SHIFT=1`,由 `base_rate.py` 标定到 base 成功率落进 30–50% 区间(实测流内 **46.3%**,分相位 0.775 → 0.350 → 0.263)。

**指标**(逐任务落 JSONL):二元成功、非法轮率、首 token 熵、全响应 mean token 熵、对 base 的**逐 token 前向/反向 KL**(在首轮响应上重算,非采样估计)、响应 token 数、wall time;每 20 任务:固定 20 任务验证集(只测不训)+ 50 段独立真实英文文本的 NLL 探针。

**臂**(同 base、同任务序、同超参):

| 臂 | 更新算子 |
|---|---|
| frozen | 不更新(同时产出 Fixed-Generation 轨迹缓存) |
| loop-imitate | 闭环无门控硬模仿:全部 episode 的全部自生成 token 做 CE |
| rft | 只对验证通过的 episode 做 CE(On-policy RFT) |
| rft-settlement | rft + Settlement 门控:每 buffer 提交前用 50 段真实文本比对候选态 NLL,退化则整 buffer 回滚(参数 + Adam 状态) |
| ascent | 冻结初始副本教师,教师输入 = z_i ⊕ c_{i,t,j}(z_i = 任务 + 成功声明 + **过滤掉非法轮**后的成功响应文本),学生做全词表前向 KL |
| loop-imitate-frozen-gen | 无门控硬模仿,但训练目标全部来自**冻结 base 的同任务轨迹**(Fixed Generation),从不来自学习者自身输出 |

**超参**(跨臂固定):LoRA r=16, α=32,注入 q/k/v/o/gate/up/down 共 196 个模块、13.7M 可训练参数;AdamW lr=1e-4, β=(0.9,0.999), wd=0;每 8 个任务一个 buffer,每 buffer 8 步,梯度裁剪 1.0;贪心解码,每轮 ≤96 token;教师取同一模块禁用适配器(= 精确的初始模型);ASCENT 的 z 在 token 级前置到学生前缀。更新是**批式**(每 8 任务一批)而非论文的逐 episode。

**ASCENT 早期损伤的落点**(任务 8–80,更新已开始):frozen 成功率 0.764 vs ascent 0.611;分族 strxform 0.944→0.667、world 0.500→0.111、calc 0.778→0.778、listops 0.833→0.889。注意同期 ascent 的非法轮数反而更低(0.28 vs 0.56)、格式合法率更高(0.960 vs 0.918)——它不是"打坏了格式",而是把 base 在易任务上的精确习惯换成了更"规范但不对"的行为;到 160–240 段它回到与 base 持平。

**四个可直接读出的现象。**

1. **只有无门控闭环真的失稳。** loop-imitate 是唯一成功率显著低于 base 的臂(−0.075,CI 排除 0),也是唯一在真实文本 NLL 上退化(+0.0141)且验证集成功率下降(0.500→0.450)的臂。它的 mean token 熵从 base 的 0.066 掉到 0.006(≈12 倍坍缩),更新损失从 0.005 降到 0.000(对自己的输出完全确定)。
2. **把生成器换成冻结 base 就几乎抹平了它。** loop-imit/frozen-gen 与原闭环的唯一区别是训练目标来自冻结 base:成功率从 −0.075 回到 −0.017(CI 跨 0,末段转正 +0.063),真实文本 NLL 从 **+0.014 翻成 −0.078**,格式合法率与非法轮率**逐位回到 base 水平**(0.888 / 0.112),验证集不再下滑,熵坍缩从 12 倍降到 2.2 倍。代价是它也**不再有增益**——这个臂的画像就是"贴着 base 走,真实文本建模略好"。
3. **verified-only 硬模仿在这个流上是大赢家,但带着失稳签名。** RFT 全程 +0.200、末段 +0.300,分族上把 calc 从 0.30 拉到 ~1.00、listops +0.45;同时熵坍缩到 0.013、格式合法率降到 0.845、非法轮率升到 0.155、KL 漂到 0.109——ASCENT 论文 Fig.1 的"漂移 + 非法动作升高"签名全在,但**没有出现"成功率跌破 base"**。
4. **在这条流上,门控不是"为稳定付代价",而是直接赢。** rft-settlement 拒掉了 30 个 buffer 中的 27 个,只提交 3 次(Buffer 16 / 32 / 184),却拿到全场最高的流内成功率 0.7083(Δ +0.246,末段 +0.388),同时把格式合法率(0.885)与非法轮率(0.116)留在 base 水平、把验证集从 0.500 抬到 0.700。三个被采纳的 buffer 分别把真实文本 NLL 从 4.4466 推到 4.4168 → 4.4153 → 4.4139,此后再无任何更新能在真实文本上不退化——**"能改善独立真实文本"与"能改善任务成功"在这条流上高度重合**。
5. **冻结教师 + 全词表软目标最稳,却在漂移的流上不涨。** ASCENT 的格式合法率 0.966、非法轮率 0.034(不到 base 的三分之一)、熵不降反升(0.085)、真实文本 NLL 改善 −0.098、固定验证集 0.500→0.700 均为稳定性指标里的最佳;但流内配对成功率 −0.050(CI 跨 0,末段恰好 0.000)。它的配对差轨迹是**先伤后追平**(0–80 段 −0.138 → 160–240 段 +0.000)。

## B1–B5 逐条判定

**B1(RFT 后段失稳:成功率跌破 base、熵坍缩、非法格式率升)——部分反驳。**
成功率部分被反驳:RFT 流内 0.6625 vs base 0.4625,末段 0.5625 vs 0.2625,配对差 +0.200 [+0.129,+0.271]、末段 +0.300 [+0.163,+0.438],方向与"跌破 base"相反。熵坍缩与非法率升**成立**:mean token 熵 0.066→0.013(末段 0.014),格式合法率 0.888→0.845(末段 0.797),非法轮率 0.112→0.155(末段 0.203),KL 到 base 0→0.109。预登记中的"失稳"若定义为"成功率跌破 base",它应判给**无门控闭环臂** loop-imitate(−0.075 [−0.121,−0.029],末段 −0.088),而不是 RFT。

**B2(ASCENT 臂稳定提升且不失稳)——部分反驳。**
稳定性一半**成立且是稳定性轴上最强的一项**:格式合法率 0.966(全场最高)、非法轮率 0.034(全场最低)、无熵坍缩(0.085,高于 base 的 0.066)、真实文本 NLL −0.0979(全场最大改善)、固定验证集 0.500→0.700。提升一半**不成立**:流内配对成功率 −0.050 [−0.108,+0.008],末段 +0.000 [−0.087,+0.087]——在这个漂移任务流上与 base 持平,既无净提升也无显著退化。两条曲线方向不一致是这条判定里最值得记住的事实:**固定验证集(级别 1–2)大幅改善,漂到 L3 的任务流只走到持平**,而且早期(任务 8–80)在 base 本已做对的易任务上净损失 13.8 个百分点。

**B3(核心结合断言:门控管稳定、hindsight 目标管提升,两者可分离)——反驳,且机制分配方向相反。**
- 门控**不仅没丢提升,反而把提升放大**:rft-settlement 的配对差 +0.246 是 RFT(+0.200)的 1.23 倍,末段 +0.388 是 RFT(+0.300)的 1.29 倍,而格式合法率(0.885)、非法轮率(0.116)回到 base 水平,KL 漂移从 0.109 压到 0.035。代价为负——**稳定与提升在这条流上不是取舍关系**。机制上说得通:30 个 buffer 里只有 3 个能通过"独立真实文本不许退化"的检验,而正是这 3 个携带了可迁移的改进;剩下 27 个的梯度方向与真实文本冲突(对应 ouroboros 的 gradient-conflict 观测)。
- hindsight 软目标**没有**带来提升:ascent 的流内配对差为 −0.050(与 base 持平),它的优势集中在稳定性、真实文本 NLL 与固定验证集。
- 第三臂把它钉死:loop-imit/frozen-gen 证明"稳定性"这个轴上还存在第三种来源——**只要切断自生成反馈**,硬目标也能稳(格式/非法轮率与 base 逐位相同)。稳定不是 hindsight 软目标的专属功效。
- 结论:**可分离性成立,归属与预登记相反**。提升 ↔ 只用已验证轨迹的(硬)目标 + 一道独立真实文本门控;稳定 ↔ 切断自生成反馈(门控、冻结生成、冻结教师软目标三种手段同向)。B3 预言的"门控只买稳定、hindsight 只买提升"被数据反向。

**B4(独立真实文本 NLL 只在硬模仿臂退化;Settlement/ASCENT 臂不变)——反驳。**
退化只出现在**无门控**的 loop-imitate(+0.0141)。同族的 loop-imit/frozen-gen 反而改善(−0.0777),有门控的硬模仿 rft 也改善(−0.0333),rft-settlement −0.0327、ascent −0.0979 同样改善。即"真实文本 NLL 探针能区分的东西"不是"硬目标 vs 软目标",而是**训练目标是否来自学习者自身当前策略**——这正是 loop-imitate(+0.014)与 loop-imit/frozen-gen(−0.078)之间 0.092 nats 的全距。

**B5(冻结 base 生成训练数据即可消除大部分伤害,即使不做软蒸馏)——支持。**
五个稳定性轴上全部朝"消除伤害"的方向移动,且是六臂里唯一在真实文本 NLL 上**由退化转为改善**的对照组:

| 指标 | loop-imitate | loop-imit / frozen-gen | base |
|---|---|---|---|
| 流内配对 Δ 成功 | −0.075 [−0.121,−0.029] | −0.017 [−0.071,+0.037] | 0 |
| 末段配对 Δ | −0.088 | +0.063 | 0 |
| 真实文本 NLL Δ | +0.0141 | **−0.0777** | 0 |
| 验证集成功 | 0.500→0.450 | 0.500→0.500 | 0.500 |
| 格式合法率 / 非法轮率 | 0.867 / 0.133 | **0.888 / 0.112** | 0.888 / 0.112 |
| mean token 熵 | 0.006 | 0.029 | 0.066 |

保留意见两条:(1) 这个臂的"伤害消除"同时伴随"增益消失",它整体是"贴着 base"的画像,所以 B5 支持的是 ouroboros 的因果主张(自生成反馈是伤害主因),不是"Fixed Generation 是更好的方法";(2) 它的训练目标与 base 自身行为几乎重合(每 buffer 平均 CE 0.005–0.057),本质上是一次自蒸馏式正则,与 ouroboros 中"冻结 W0 生成、另一个学习者学习"的设定同构。

## 局限与已知偏离

- **单种子**(seed=1234)、单模型(Qwen3-0.6B)、单任务流(240 任务,合成任务族)。所有 CI 都是任务级 bootstrap,不含跨种子方差;数字不可外推,结论应读作"在这个受控流上几种更新算子的相对排序"。
- **批式更新**:每 8 任务一个 buffer、8 步,而两篇论文都是逐 episode 更新。批式平均降低单样本噪声,系统性地**弱化**了失稳,这可能是 RFT 没有跌破 base 的部分原因。
- **rft-settlement 跑了两遍**。第一版在回滚候选态时只还原了参数、没有还原 Adam 动量(被拒更新的动量会带进下一次候选),相对 ouroboros"候选态在临时模型上评估、提交态独立"的定义有偏离;修正版把整份优化器 state_dict 深拷贝后回滚(见 `code/harness.py` 的 `opt_state_clone` 与 `buffer_update`)。**表中数字来自修正版**(30 个 buffer 中只提交 16/32/184 三个)。第一版对照数字:成功率 0.6000、Δ +0.1375 [+0.075,+0.204]、末段 +0.213、验证集 0.500→0.650、真实文本 NLL −0.0088——**结论方向不变,修正后更强**。这说明"门控的收益幅度"对本实现细节敏感(被拒更新是否污染优化器状态),属于应当被独立复现的边界,但"门控不亏稳定且不亏提升"这一方向在两版里都成立。
- **ASCENT 的 z 是 token 级前置**(z 的 token id 直接拼在学生前缀前),不是论文的文本级序列化;由此产生的分词边界伪影未量化。论文自己指出的"教师上下文含学生回复文本、可能部分重建目标 token"的限制在这里同样存在。
- **轮预算**把失败 episode 封在 5–7 轮;ASCENT 论文的 50 轮长程设定被大幅压缩,长程 credit assignment 的效应空间更小。
- **未做**:EMA/快照教师消融(ASCENT App. 8.1 的关键表)、多种子、真实 agent 基准(ALFWorld/WebShop);任务族虽是工具型 agentic 任务,但仍是合成的。
- 每次更新只取 buffer 内的轨迹,**无 replay**;这与 ASCENT 的在线单遍协议一致。

## 复现与成本

```bash
# 远端(Inspire 4090,ngc-pytorch:25.02,venv 继承 NGC torch 2.7+cu128)
export TTT_MODEL=<workroot>/cache/models/Qwen3-0.6B TTT_LEVEL_SHIFT=1
export PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True
python selftest.py                    # 位置对齐/LoRA 恒等/损耗自检(必须先过)
python base_rate.py 120 1234          # 难度标定:base 成功率 ~0.46
bash run_all.sh <results-dir>         # frozen → loop-imitate → rft → rft-settlement → ascent → fixed-gen
python analyze.py <results-dir> code/analysis <assets-dir>
```
`run_all.sh` 幂等:每臂每 buffer 存 checkpoint,实例被停/重启后重跑即从最近 buffer 续(本次运行中实例未重启,墙钟中断不影响远端进程)。单臂 `python run_arm.py --arm X --out-dir <dir>`。**注意**:`frozen` 臂必须最先跑,它产出的 `frozen_trainids.jsonl` 是 fixed-gen 臂的训练数据。

成本(单卡 4090,实测):六臂流内 240 任务 + 12 个验证点 ≈ **2.0 GPU·h**(逐臂 wall 769/1071/965/1116/929/1132 s,加 Settlement 重跑 1212 s);加环境搭建、模型下载、标定、自检与早期调参,总计约 **3.2 GPU·h**。生成 ~1.4 s/任务,峰值显存 7 GiB。
