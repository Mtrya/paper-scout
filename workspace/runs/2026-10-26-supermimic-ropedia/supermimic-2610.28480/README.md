# SuperMimic：可微世界模型的效率、训练覆盖与未见动作

论文：Liao et al., *SuperMimic: Scaling Humanoid Whole-Body Control with One Differentiable World Model*，arXiv 2610.28480，CoRL 2026 oral。项目页 https://supermimic.github.io 。截至本轮调查，官方页面未提供完整训练代码；浏览器 demo 暴露了 `weights.bin` 和 `engine.wasm`，两者不是同一物。

## 研究问题

一个可微世界模型能否把人形全身动作跟踪的训练成本大幅压低？论文的效率对照与训练集覆盖能证明什么？对没有见过的动作，误差更可能来自世界模型、策略，还是长时跟踪？本线程分别核查原论文、直接前作、公开复现与本机缩小配置实验，不把不同证据层级混成一个分数。

## 方法与前作

动作跟踪给策略一段人形参考动作，要求机器人通过关节位置控制跟随。SuperMimic 从 MuJoCo Warp 记录的状态、动作转移学习可微世界模型，在长度为 32 的想象轨迹上反向传播回报；价值网络为超出想象窗口的未来自举。策略、价值网络与世界模型在同一训练回路中更新。论文最有判别力的机制证据不是跨系统算力比，而是：

- LAFAN1 上 PPO-Sim 与它共享动作、观测、奖励、终止、域随机化、网络和评测，1.2 小时达到 0.82 对 18 小时内未达到；
- 两种策略更新都基于世界模型想象轨迹，解析梯度用约 1/64 的想象步达到 PPO-WM 的最佳训练回报；
- H100 上世界模型在实际使用批量下的轨迹生成速度超过 MuJoCo Warp 十倍，最大对比为 62 倍。

这些是作者实验，不是本巡航独立复刻。本机训练规模与显卡不同，不能复写其 1.2 小时或 3 小时的墙钟结论。

## SONIC 对照：能说什么，不能说什么

[SONIC 原文](https://arxiv.org/abs/2511.07820) 与 SuperMimic 都继承 BeyondMimic 的动作跟踪设定。我们读取了 SONIC 的方法、奖励、数据划分和不同算力实验，结论需要收窄。

### 成本账目

SuperMimic 以 SONIC 的 128 GPU、7 天训练为分母，以单张 H100 的 3 小时为分子，给出约 7200 倍 GPU·h 比，并保守声称超过 1000 倍。3 小时是回报超过 SONIC released checkpoint 的时间，不是完成 320k 迭代，也不是零失败时间；它不含离线检查点评价。L40 型号来自 SuperMimic 对 SONIC 硬件的归属，SONIC 原文未写型号。

这组数字是不同方法、数据、训练目标和工程实现的作者报告成本比，不是可微梯度相对 PPO 的受控加速倍率。SONIC 有 16/32/128 GPU、约 2k/9k/21k GPU·h 的不同训练规模，不能拿最昂贵一档证明所有配置都需要同样成本。尤其不能把 32 GPU 量化器扫描的 98.8% 与另一项 128 GPU 量化器实验的 99.3% 拼成受控算力对照。

### 回报、失败与覆盖

SuperMimic 的正奖励每步最高为 0.1：四个刚体项权重各 1、两个根部项各 0.5，再乘控制周期 0.02s。SONIC 的训练奖励还含权重 2、尺度 0.1m 的末端位置项，以及不希望接触、防抖动、足部加速度等惩罚，关节限位权重也不同。

SuperMimic 的评测说明明确了共同动作集、共同仿真、各自观测与执行器、统一采用 SuperMimic 终止判据，但没有完整交代 SONIC 的回报究竟按哪套奖励与分母计算。因此可写“双方训练目标不同，公开文本未证明评分口径已对齐”，不能断言 SONIC 一定按 SuperMimic 的奖励被不利打分。两套终止判据也都有对方没有的项，净方向未知；不能用不同数据与协议的成功率推断其净效应很小。

论文报告在 129,514 条过滤后的 BONES-SEED 动作上，SONIC released checkpoint 失败 179 条，SuperMimic 单卡 3 小时失败 25 条，双卡 9.8 小时失败 0 条。双卡成本为 19.6 GPU·h。原文明确说这些动作是双方训练动作，衡量的是训练覆盖，不是未见动作泛化。

SONIC 另有真正留出：test-content 的类别整体未见，基线比较为 98.5%，最大模型的 scaling 实验为 99.6%；外部 PHUMA 为 97.2%。这些数字与 SuperMimic 的训练覆盖不是同一评测，不能排成泛化胜负。

## 公开实现透露的敏感点

两份公开复现是他人公开日志，本巡航核对了实现与协议，但没有重跑其全部曲线。

- [zita-ch/supermimic_vibed](https://github.com/zita-ch/supermimic_vibed) 报告在 RTX PRO 6000 上以 1.47 小时达到 0.829，40 条 LAFAN1 无提前失败。其 actor 在本体量之外加入参考根部相对当前根部的完整旋转 6D，critic 另看根部和刚体误差。未来目标中的相对路径是参考内部的轨迹，不等于机器人相对参考的位置误差。
- [CuboiLeo/SuperMimic-Reproduced](https://github.com/CuboiLeo/SuperMimic-Reproduced) 的两种观测方案差异明显：纯参考目标的多台运行配置在其实际执行步归一化下约到 0.56；给目标加入参考锚点在机器人锚点坐标系下的三维位置与六维旋转后，1.66 小时到 0.824，伴随 5/40 提前失败；后续 0.904 也伴随 3/40 失败。它们不是论文整段回报的严格复现。所谓“两台机器”是 1×5090 与另一台 4×5090 机器，不是三台。

两份实现共同支持的是：论文未完整说明的目标表示会显著影响复现，且可行设计都会引入某种根部相对信息。不能由此断言官方缺少某个必需的九维锚点，也不能把奖励的坐标重锚误认为 actor 一定看到了位置误差。

[MorphMimic 技术报告](https://lzyang2000.github.io/morphmimic) 则把同类训练扩展到 G1、X2 Ultra、T2。position-free 指 actor 不需要机器人全局位置定位，不是不需要位置目标或朝向反馈：目标位置在首帧参考骨盆朝向系中，目标朝向相对当前躯干；训练 critic 另接收参考锚点相对当前锚点的位置。统一模型在 128,786 条共同训练动作上与专家差不超过 0.02 return，16.3 GPU·h 对三个专家合计 13.9 GPU·h，成本约多 17%，不是节省。它也有跨本体 zero-shot 试验，但动作仍来自共同训练集，不能替代跨动作泛化。

CuboiLeo 实现把状态写成 71 维 MuJoCo qpos/qvel，学习动力学与终止头，奖励和观测由解析公式计算。这是该实现的结构，不能反推官方所有头都是解析的。该复现的八步归一化误差尺度由复现者选定，论文只说 predefined nominal error 而未公开数值，不能称二者指标定义一致。

## 官方 demo 探针为何弃用

本巡航尝试在 demo 的真实引擎中注入状态并运行策略，策略动作确实随状态改变。但参考轨迹通道与公开 LAFAN1 对齐后仍无法核验，若干演示出现与官方页面不一致的倒地。为避免把未知参考、坐标或初始化问题当成泛化结论，所有来自该路径的数字都弃用。本机实验只走透明的 CuboiLeo 路线，不声称使用官方权重。

## 本机实验设计

- 数据：40 条 LAFAN1，合计 2.451 小时；数量与总时长与论文相符，但论文没有公开逐条清单，不能声称逐条数据完全相同。
- 划分：`code/splits/train30.txt` 与 `code/splits/heldout10.txt`，30 条训练、10 条留出，按动作族与不同表演者配对，在结果前固定。
- 训练：单张 RTX 3060 12GB，1024 仿真环境、1024 想象批量，32k 迭代，开启上述九维锚点目标输入。论文主配置为 4096 环境/批量、320k 迭代，故这是缩小配置下的机制探针，不是完整复刻。
- 评价：每条动作从首帧开始，确定性策略，无域随机化、观测/动作噪声，使用 50Hz 控制。每条动作独立计算整段回报，再对片段等权平均。SuperMimic 未明确跨片段等权还是帧加权，这里的选择必须明示。
- 次级诊断：根部平移与偏航漂移、世界系和去偏航后的速度误差；同动作不同表演者的世界模型一步/八步开环误差。世界模型在策略真实仿真轨迹上重放，物理量误差由归一化误差乘回尺度获得。八步只有 0.16s，不能替代长程稳定性。漂移脚本保存的速度数值是先对平方误差取时间平均再做指数核变换，不等于逐步奖励的平均；最终报告若使用这项诊断，只引用平移、偏航等直接物理量，不混淆两种平均。

### 整段回报定义与公开复现的协议修正

设一条参考有 L 个状态帧，实际执行 n 个控制转移，逐步奖励为 r_t，则本实验的整段归一化回报为：

R = sum(r_t, t=1..n) / [0.1 (L−1)]。

提前失败后未获得的未来奖励保留在分母中，不能除以实际执行步数把早停“除掉”。L−1 的定义与同组 MorphMimic 技术报告和 zita-ch 的评测一致；SuperMimic 正文只说整回合最大回报、早停扣分，没有展开 off-by-one。

审计发现 CuboiLeo 的 `eval/benchmark.py` 除以实际执行步数；成功片段还会多一个末尾转移，重置后参考帧从 0 前进到 1。`patches/whole-clip-evaluation.patch` 修正评测器：显式重置并对齐参考首帧，到末帧停止，按 L−1 归一化，限制队列结束游标。`code/test_benchmark.py` 在真实物理环境、真实训练权重上验证长短混合队列；`code/results/benchmark_test.log` 记录最终测试结果。旧的换算曲线和数字全部弃用，早期检查点按修正协议重跑，结果另存于 `eval_fixed/`。

### 世界模型误差的尺度

复现的归一化平方误差对 70 个状态分量分别除以名义尺度：根位置 0.05m、根旋转 0.1rad、根线速度 0.5m/s、根角速度 1rad/s、关节位置 0.1rad、关节速度 2rad/s，再对分量求均方。四类根状态各占 3 维，关节位置与速度各占 29 维，均方按 70 维等权而非六类等权。每条轨迹对从第 0 步开始、步长为 8 的非重叠完整窗口取均值，九组配对的中位数再分别对九条训练与九条留出逐轨迹值取中位数，不汇集全部窗口。这个误差不是米制跟踪误差，也不是失败概率。物理分解把同一个误差向量乘回这些尺度，再对窗口求 RMS；同一 checkpoint 的同族动作配对比跨 split 的总平均更有判别力。

## 32k 最终结果与同轨迹口径

修正协议的整段评价显示，30 条训练动作的平均回报为 0.7392，提前失败 3 条；10 条留出动作的平均回报为 0.5090，提前失败 6 条。24k 时两者分别为 0.7022/5 条和 0.5667/4 条：训练集继续改善，留出集却退步。留出侧并非全部恶化，舞蹈 1、冲刺与两条步行的整段回报仍超过 0.76；舞蹈 2、跑步与格斗的提前终止拉低了均值。单次训练、单次评价和 10 条留出不能支持总体泛化率结论，也不能把这条曲线直接对齐论文完整配置的 0.82。

九组同族配对中，世界模型一步误差的中位数为训练 0.00723、留出 0.00730，八步误差的中位数为 0.01499 与 0.02135；后一个中位数约高 42%，但只有 5/9 对的留出误差更大。误差与策略成败不一一对应：fallAndGetUp1 的训练轨迹八步误差 0.04923、整段回报 0.6282 且完整结束，留出轨迹误差略低的 0.04701，却在 421 步以姿态终止、回报 0.0401。dance2 的训练轨迹误差 0.00999 且提前失败，留出轨迹误差更高的 0.02135 却完整结束、回报 0.6362。短窗口误差值得测，但不能独自解释泛化失败，策略与目标接口仍需分别检查。

`code/results/wm_pairs.json` 和 `code/results/wm_nse_paired_0032000.json` 来自修正后的探针。它在记录状态与动作的同一条策略 rollout 内累计奖励，保存 `policy_return_full_clip`、`policy_failed` 和 `policy_steps`，不再从独立评价文件拼接回报。同一 checkpoint 的多次仿真 rollout 可能出现不同终止步，此前跨文件配对已弃用。独立评价曲线仍按上述整段口径；配对图的回报与模型误差则严格共享轨迹。环境批量、仿真数值轨迹与长时接触结果之间存在敏感性，不把终止步差异改写成固定的动作标签。

补充漂移诊断 `code/results/drift_failure_causes_0032000.json` 记录 10 条留出的另一次重放：5 条提前终止，2 条触发根高度阈值，2 条触发姿态阈值。管理器的终止判定与命令刷新之间有物理子步差异，刷新后重算未超阈值的片段不强行归类为“摔倒”。重置必须覆盖全部 done 环境，包括已经结束、不再记录的槽位；否则底层环境会拒绝再次步进。诊断脚本的指数速度量是平均平方误差的核变换，不是逐步奖励均值。

结果证据包括 `code/results/policy_summary.json`、逐检查点的 `code/results/evaluations/`、配对汇总与原始探针、失败原因诊断，以及报告用的 `assets/sm_policy_progress.png` 和 `assets/sm_wm_pairs.png`。

## 重跑与产物

训练配置摘要保存在 `code/results/experiment_config.json`，实际训练调用保存在 `code/train_local.sh`。原始 checkpoint、数据和视频不入包。保留的脚本包括目标划分、评价、漂移诊断、世界模型探针、分析、回归测试与整段评价补丁。修正后的曲线、最终配对结果和测试日志在完成后晋升到 `code/results/`。

```bash
# 在 CuboiLeo/SuperMimic-Reproduced 仓库中应用评价补丁后
python -m pytest tests/test_benchmark.py -q
bash code/finish_local_experiments.sh
```

接力脚本从 workspace 的 ignored `code/` 启动，先复跑早期整段评价，再等待 32k 检查点与常规里程碑完成，运行 19 条配对世界模型探针，最后执行 Ropedia 本机生成。若训练或评价失败，它会停止，不把缺失结果补成结论。

本轮基于 CuboiLeo/SuperMimic-Reproduced 的 `d9be385b3eeb13a638fb33fb200d3bfd9be9839f`，不是作者官方实现。准备环境时在该提交运行 `uv sync --group dev`；将 [LAFAN1 重定向数据集](https://huggingface.co/datasets/lvhaidong/LAFAN1_Retargeting_Dataset) 的 `g1/` 目录放到 `data/raw/lafan1/g1`，转换命令为：

```bash
env -u PYTHONPATH .venv/bin/python scripts/data/csv_to_npz_batch.py \
  --input-dir data/raw/lafan1/g1 --output-dir data/npz/lafan1 --input-fps 30
```

线程包中 `eval_benchmark.py`、`wm_nse_probe.py`、`diag_drift.py` 对应仓库 `scripts/` 下的同名文件，`test_benchmark.py` 放入 `tests/`，`splits/` 复制为 `data/splits/`，`whole-clip-evaluation.patch` 应用于上述上游提交。`train_local.sh` 是实际训练调用，在仓库根目录执行；`eval_milestones.sh`、`finish_local_experiments.sh` 与两个分析脚本放在 workspace 的 ignored `code/` 下执行。训练默认随机种子为 0，九维锚点目标输入显式开启。原始数据、虚拟环境、TensorBoard、checkpoint、生成的视频、Ropedia 权重及本地手部检测模型在收尾时删除，运行包不保存这些大文件。
