# REA 运行时契约探针：四门控对比、判官噪声扫描与异步建议年龄

## 研究问题

REA（arXiv 2610.42053）主张具身智能体的快慢耦合应落在运行时契约上：route memory 免打扰派发、边界触发判官门、共享预算升级梯，黄金法则是"任何运行中的策略不等大脑"。论文的关键经验声称有三条：(1) 异常门对静默失败几乎全盲（LIBERO-Pro 590 集中 166 例失败仅触发 6 次升级）；(2) 判官门在匹配困难子集上比异常门高 15.3%；(3) 判官整体精度有限（0.67–0.72）但 done 判决精度高（0.83–0.905），系统层面仍净赚。本探针在 REA 开源运行时源码上构建最小抽屉玩具，独立复现门控分化，并把判官的两种错误拆开定量扫描；另做一组异步扫描，检验"建议年龄上限必须覆盖大脑延迟"这一运行时约束。

## 结论

1. **异常门对静默失败信息量为零**：异常门与单快策略完全同分（成功率 0.4975，400 seeds/格），因为玩具中的失败以"零异常返回"的形式发生。
2. **盲目恢复的两种形态都输给判官门**：同策略盲目重试仍 0.4975（6 步，持久失败重试无用）；全梯盲目升级拿到 1.0 但固定 14 步；无噪声判官门 1.0 且 7.02 步/集（1.5 次判官调用/集）。
3. **判官噪声不对称律**：假 not_done 率 β 只加步数（7.02→8.27→10.31 @ β=0/0.2/0.5），成功率恒 1.0；假 done 率 α 线性没收成功率，success = 1 − p_jam·α（实测 0.98/0.9575/0.8925/0.8300 @ α=0.05/0.1/0.2/0.3，p_jam=0.5）。停止权可以交给整体精度有限的判官，前提是它把"宣布完成"捂紧。
4. **异步扫描（探针 B）**：建议年龄上限 maxAdviceAgeSteps 必须不小于大脑延迟折算的步数，否则建议到达时已被弃置（applied=0，机器人卡障碍 24 步失败）；大脑 6000ms 时建议到得太晚，剩余预算不够绕行，全格失败。同步 vs 异步墙钟：8006→4259ms（brain 1350ms）、12961→5779ms（brain 3000ms），异步阻塞 0ms。

## 材料与口径

- 论文精读缓存：`papers/agents/rea-2610.42053.md`；官方代码：`code/REA/`（route-memory.mjs、judge-gate.mjs、routed-runtime.mjs、async-runtime.mjs 已通读）。
- 玩具环境：抽象抽屉状态机。快策略执行 3 步，以 p_jam=0.5 概率卡阻并静默返回（无异常标记）；慢策略 8 步必成功。判官无噪声时完美区分 done/not_done；噪声扫描注入假 done 率 α = P(done|not_done) 与假 not_done 率 β = P(not_done|done)。
- 门控变体：never-fast（单快）、never-slow（单慢）、exception（异常门）、always-same（同策略重试）、always（全梯升级）、judge（判官门）。每格 400 seeds。
- 探针 B：async 运行时，brainMs ∈ {100,500,1350,3000,6000} × maxAdviceAgeSteps ∈ {0,1,3,6,12,24}，记录成功率、步数、墙钟、建议采纳数与过期事件。
- 文件：`code/probe.mjs`（探针脚本）、`code/results_a.json`（门控+噪声扫描）、`code/results_b.json`(异步扫描)；报告配图由 `code/make_figs.py` 生成。
