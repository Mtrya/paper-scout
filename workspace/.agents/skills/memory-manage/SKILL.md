# memory-manage

记忆服务于跨巡航复用,不是运行摘要。原始过程留在运行跟踪产物,完整证据留在 `runs/<run-id>/`;这里只保存未来研究或执行会实际用到的判断。巡航中主要检索记忆;写入发生在报告与运行包稳定之后,可以由独立的记忆会话完成,失败时保留来源并重试,不改变已经完成的交付状态。

## 文件边界

- `memories/MEMORY.md`:进 git 的近稳定入口,只保存长期研究主线、读者信息和记忆边界。不要把它改成日期文件或条目索引;只有这些长期内容发生变化时才更新。
- `memories/<date>-memory.md`:进 git 的日期记忆。一次巡航只写一个日期文件,文件内可有多条 typed entry。
- `runs/INDEX.md`:覆盖与去重事实源,不是记忆索引。
- `runs/<run-id>/`:报告与证据事实源。记忆条目只提炼结论并链接回来,不复制完整过程。

## 检索

1. 巡航开始时读 `memories/MEMORY.md` 与 `runs/INDEX.md`。只有当前动作依赖本机或平台环境时才读 gitignore 的 `INSPIRE.md`。
2. 从当前论文、方法、数据集、现象、工具和错误文本中提取一组具体查询词,同时包含正式名称、缩写与别名。
3. 先用 `rg -n -i '<term1>|<term2>' memories/*-memory.md` 搜 `keywords:` 与条目标题;没有命中或需要找反例时再搜正文。不要默认通读全部日期文件。
4. 打开命中的完整条目及其 `source`。形成猜想、设计实验或写新条目前,再次搜索同题条目,确认新证据是在延续、挑战还是取代既有判断。
5. 没有明确检索目标时,只读最近一两期日期记忆获取近期上下文。

`keywords` 是检索入口。写入论文名、arXiv id、方法、数据集、现象、指标、工具、平台和具有辨识度的错误文本;同时写必要的中英文别名。不要只写 `robotics`、`experiment` 之类宽泛词。

## 条目路由

- `hypothesis`:关于研究对象的可检验命题,记录适用条件、证据与当前判断。观察发生在提出猜想之前也可以晋升为 hypothesis,前提是它对未来研究有判别价值。
- `execution`:关于怎样可靠完成研究或交付动作的可复用经验,记录条件、结果、失败模式与恢复办法。可移植且已脱敏的内容可进入日期记忆;本机或敏感内容只进 gitignore 的 `INSPIRE.md`。会随环境变化而失效的经验(镜像速率、平台镜像版本、CLI 行为细节)也只进 `INSPIRE.md`,日期记忆留给跨环境稳定的判断。

不要把论文摘要、完整命令流水、已由报告充分承载的一次性数字、无后续价值的成功步骤、凭据或原始环境转储写成记忆。一次巡航可以没有值得新增的条目。

## 通用格式

日期文件以 `# <date> 巡航记忆` 开头,随后用二级标题分隔条目:

```md
## 猜想:<稳定、可检索的命题标题>
- type: hypothesis
- keywords: <逗号分隔的具体检索词>
- source: <run packet 或证据路径>
```

或:

```md
## 执行:<稳定、可检索的能力标题>
- type: execution
- keywords: <逗号分隔的具体检索词>
- source: <run packet 或其他可定位证据路径>
```

同一主题在后续巡航再次出现时复用原条目标题,并用 `updates:` 或 `supersedes:` 写明较早的日期文件与条目标题。不要回写旧日期文件来抹平判断变化。

## Hypothesis schema

每条 hypothesis 使用这些元数据:

```md
- type: hypothesis
- keywords: ...
- status: open | supported | weakened | refuted | mixed | superseded
- confidence: low | medium | high
- scope: <当前判断成立的对象、数据、模型、环境或其他边界>
- source: ...
```

正文依次使用:

- `### 动机`:为什么提出这个可检验命题。
- `### 支持证据`:观察、方法、条件与证据位置。
- `### 反对证据`:反例、矛盾结果或明确写“暂无”。
- `### 当前判断`:在 scope 内能说到什么程度,以及不能外推到哪里。
- `### 下一项判别性实验`:最能区分竞争解释的下一步;没有合理下一步时说明原因。

`status` 与 `confidence` 分开判断。保留互相矛盾的证据,不要用最新结论覆盖历史。单次实验通常只能支持有边界的判断,不要轻率使用无条件的“证明”。

## Execution schema

每条 execution 使用这些元数据:

```md
- type: execution
- keywords: ...
- outcome: working | degraded | failed | superseded
- verified: YYYY-MM-DD
- applies-when: <适用环境与触发条件>
- invalidated-by: <哪些变化要求重新核验>
- source: ...
```

正文依次使用:

- `### 目标与背景`:想完成什么,为什么值得记。
- `### 实际执行`:足以解释结论的动作,不是逐命令抄录。
- `### 观察结果`:成功、失败或退化的具体表现。
- `### 可复用做法`:下次应直接采用的路径。
- `### 失败信号与恢复`:症状、原因和恢复动作;没有则说明暂无已知失败。
- `### 边界`:不可移植部分、残余风险和需要复核的条件。

## 写入与维护

1. 只从已经稳定的运行跟踪、报告和运行包中提炼,不要把工作中尚未核验的直觉直接升级为记忆。
2. 先分类再写:研究对象的判断进 hypothesis;研究或交付动作的复用经验进 execution。
3. 选择真正影响未来决策的内容。每条必须有 `keywords` 和 `source`;证据不可定位时不写确定性结论。
4. 使用本次巡航日期写入唯一的 `memories/<date>-memory.md`;同日已有文件时在其中追加或修订,不创建编号变体。
5. 后续证据改变判断时在新的日期文件添加同题条目,用 `updates` 或 `supersedes` 串联,保留原记录。
6. 只有长期研究主线、读者信息或记忆边界改变时才更新 `memories/MEMORY.md`;不要为每次巡航刷新它。
7. 写完后检查路径存在、字段完整、没有秘密或本机敏感信息,再用关键词搜索一次,确认条目能够被找回且没有重复制造同义条目。
