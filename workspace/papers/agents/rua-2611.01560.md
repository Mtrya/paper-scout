Abstract

   Robot-use agents (RUAs) have shown promising zero-shot manipulation
   capabilities, but reliance on frontier, proprietary models limits
   research into further training. To democratize RUA research, we
   introduce uni-robot-agent, a unified harness for competitive
   open-weight robot use that supports further training. Without
   privileged inputs, an out-of-the-box Qwen3.8-Flash-Next achieves a
   RoboDojo Score of 31.39, surpassing the published GPT-6 Astra–RoboProbe
   result of 28.97 and many VLA/WAM baselines, and performs competitively
   on 19 real-world tasks. Our analysis across model generations,
   families, and sizes links effective robot use to four general
   capabilities, suggesting that future RUA training should develop them
   jointly.

1 Introduction

   Recent breakthroughs in frontier foundation models (e.g., GPT-6 Astra
   (OpenAI, 2026c), Opus 5.5 (Anthropic, 2026)) have shown surprising
   zero-shot performance in robotic manipulation, highlighting robot-use
   agents (RUAs) (Isola, 2026) as a promising approach for robotics (Chen
   et al., 2026b; Zhang et al., 2026b; Qu et al., 2026). This approach
   effectively transfers the models’ generic problem-solving capabilities,
   such as task decomposition and failure recovery, which are hard to
   learn from limited robotics data alone, yet extremely useful for
   robotics (Isola, 2026; Chu et al., 2026; Jia et al., 2026).

   However, because these frontier foundation models are proprietary,
   research on RUAs has been limited to using the models as-is, such as
   harness design (Li et al., 2026; Zhang et al., 2026b; Si et al., 2026).
   Without access to their weights, researchers cannot directly explore
   how further training of these models can advance RUA capabilities.
   Moreover, API dependence makes large-scale interaction costly (OpenAI,
   2026c) and restricts model-level optimization, such as efficient
   caching, despite inference speed being a major bottleneck for RUA
   (Isola, 2026).

   The main challenge in adapting open-weight models for robot use is the
   capability gap between open-weight and closed-weight foundation models.
   Robot use demands strong spatial understanding and agentic
   capabilities, which existing open-weight models often lack.
   Consequently, prior work has focused on ad-hoc improvements, including
   leveraging privileged information such as ground-truth simulator states
   or oracle task-success feedback (Fu et al., 2026; Zhang et al., 2026c),
   or incorporating task-specific skills (Lu et al., 2026). Before
   attributing these limitations to the models themselves and pursuing
   ad-hoc improvements, we argue that we must first establish a
   generalizable and effective robot-use harness to systematically
   understand and maximize their existing capabilities, laying the
   foundation for future RUA training.

   In this paper, we take a first step toward democratizing robot-use
   agent research by laying this foundation for both competitive
   open-weight agents and future robot-specific training. We introduce
   uni-robot-agent, a general-purpose RUA harness. It provides Unified
   tool interfaces and feedback formats across models, embodiments, tasks,
   and environments, supporting joint training on simulation and
   real-world interaction data. For future large-scale training, we
   emphasize Efficiency by overlapping model reasoning with tool execution
   to accelerate interaction, and Modularity through interchangeable agent
   runtimes, tools, and robot backends. Together, these designs provide a
   scalable, extensible foundation for RUA research.

   The proposed uni-robot-agent enables competitive manipulation
   performance with open-weight models, including Qwen and DeepSeek, in
   both simulation and physical environments. A key finding is that
   well-structured information, such as camera calibration and robot
   descriptions, together with reliable tool interfaces that provide
   informative feedback, are sufficient for effective robot use. As a
   result, without privileged inputs, Qwen3.8-Flash-Next with
   uni-robot-agent achieves a Score of 31.39, surpassing GPT-6 Astra’s
   result (28.97) on RoboDojo (Chen et al., 2026a) from the RoboDojo team
   (Zhang et al., 2026a). To the best of our knowledge, this is the first
   system to outperform closed-weight foundation models on RoboDojo using
   open-weight models, without privileged informations or distillation
   from those closed-weight models. In real-world experiments on 19
   tabletop manipulation tasks, Qwen3.8-Flash-Next with uni-robot-agent
   achieves a Score of 49.50, outperforming Dream-1 (35.50; Dream Labs,
   2026) and matching fine-tuned

   encoding="application/x-tex">\pi_{0.5}</annotation></semantics> :MATH]
   (47.75; Physical Intelligence et al., 2025).

   Having established the competitiveness of open-weight RUAs, we further
   compare models across generations, families, and sizes to investigate
   the capabilities underlying robot use. Trajectory analysis reveals four
   common failure patterns involving visual understanding, spatial
   grounding, geometric coding, and embodied reasoning. Based on these
   findings, we posit that current robot-use capability emerges from a
   combination of these general-purpose capabilities and identify them as
   key areas for improvement in future RUA training. Finally, we provide
   an analysis of the effect of privileged information, cost, and
   execution efficiency.

2 uni-robot-agent: A Unified and Modular Harness

   In this section, we introduce the key mechanisms of uni-robot-agent. We
   describe how the harness connects diverse agents, robot environments,
   and embodiments through shared tools and supports interaction based on
   information only available in real-world deployments.

2.1 System Overview

   uni-robot-agent connects different agent runtimes to a shared toolkit
   for simulation and physical robots. The agent selects operations using
   task instructions and observations, while the harness executes them and
   returns feedback. We organize this interaction around four principles:
     * •
       Unified. Shared tools give operations and feedback a common meaning
       across environments, with adapters handling native APIs (Section
       2.2). The resulting interaction records can also be combined for
       subsequent training.
     * •
       Efficient. Reasoning should overlap physical execution, while
       operations that share a resource retain their required order
       (Section 2.3).
     * •
       Realistic. Agents and tools should rely on information available in
       physical deployments, without simulator-provided depth or
       task-verifier feedback (Section 2.4).
     * •
       Modular. Explicit interfaces should allow researchers to replace
       runtimes, tools, and perception models independently. We introduce
       this architecture below.

   These principles guide how we organize the system, but reliable
   interaction also requires care in how observations, actions, and
   feedback are handled. We first describe the architecture, then examine
   these practical design choices in Section 2.5.

Modular Architecture.

   A tool call passes through five layers with explicit interfaces (Figure
   2). The agent layer manages model interaction and context, passing tool
   requests to the orchestration layer for scheduling and dispatch. The
   tool layer implements shared robot operations and accesses environment,
   perception, and action-model capabilities through the service layer,
   which manages their runtime resources. The backend layer supplies the
   concrete simulator, robot, and model implementations used by these
   services. Results return through these interfaces to the agent,
   completing the interaction.

2.2 Unified Interaction Interface

   Moving a gripper to a target pose should mean the same thing in
   simulation and on a physical robot, even when their control APIs
   differ. We give agents a shared set of tools for motion, perception,
   skills, and episode control, with common arguments, units, and feedback
   formats. Environment descriptions identify the available arms, cameras,
   and optional capabilities. This lets the agent use familiar operations
   while accounting for the robot and sensors available in each
   environment.

2.3 Efficient Execution

   The orchestration layer determines how agent interaction proceeds while
   tools are running. Waiting for every movement to finish delays
   reasoning that could proceed independently, yet successive movements
   may still need to execute in order. We combine background tool calls
   with resource-aware scheduling to satisfy both requirements, forming a
   pipeline between agent reasoning and tool execution.

Two Levels of Concurrency.

   The agent need not wait for every tool, but its next call may still
   need to wait for a resource:
     * •
       Between agent and tools. A background call returns a job handle,
       allowing the agent to continue independent reasoning and retrieve
       the result later; an immediate call waits for completion. Decisions
       that depend on the result must still wait.
     * •
       Among tool calls. Calls sharing an exclusive resource execute in
       submission order; parallel calls run outside that queue. Two move
       calls on the same resource therefore run sequentially, while
       reading an existing snapshot can overlap movement.

   Two-Stage Pipelining. These mechanisms enable a two-stage pipeline
   comprising agent reasoning and tool execution (Figure 2.3). The agent
   can submit successive calls while previously submitted calls execute in
   resource order. Reasoning and execution thus overlap even when the
   tools themselves execute sequentially. When observations or execution
   feedback require a change of plan, the agent can use flush_queue to
   cancel calls that have not started for a specified resource. Where
   supported, a single model response can submit multiple tool requests,
   and a batched wait can retrieve multiple results.

2.4 Interaction Without Privileged Inputs

   Efficient execution alone does not ensure that simulation performance
   carries over to physical robots: the information supporting each action
   also matters. Existing systems provide depth-based geometry and
   completion checks (Li et al., 2026), or construct object models to
   maintain a virtual scene (Wang et al., 2026). In physical settings,
   depth measurements can vary or be missing even in a static scene, and
   simulator task-verifier feedback is unavailable. These differences
   motivate testing whether agents can infer spatial relationships and
   assess progress from more limited observations.

2.5 Key Design Choices

   Effective robot use requires careful design of how observations reach
   the agent, how commands are executed, and how outcomes inform
   subsequent decisions. We introduce six practical design choices
   spanning observation and execution consistency, coordinated motion
   control, progress monitoring, actionable feedback, and visual context
   management.
   Figure 5: Key design choices. Each column pairs two designs for
   physical consistency, action precision, or context management.

Keeping Observations and State Consistent.

   When a robot moves after an image is captured, interpreting a selected
   pixel using a newer camera pose mixes two physical states. We bind
   images, camera calibration, and robot state to an immutable snapshot
   and use that snapshot for localization (Figure 5). The agent and tools
   thus work from the same recorded state.

Preventing Repeated Actions After Communication Failures.

   The agent must also know which actions have occurred: a missing reply
   may mean lost feedback, so retrying could repeat a physical action. We
   record request identities and execution status to reject duplicates
   (Figure 5). If completion is uncertain, further actions are blocked
   while the session attempts to recover the execution record; unresolved
   requests remain explicitly marked as uncertain.

Coordinating Motion and Gripper Control.

   Separate movement and gripper commands prevent the agent from adjusting
   the opening during a movement. Our move tool accepts a target pose and
   an optional gripper opening together, allowing the arm and gripper to
   act simultaneously (Figure 5).

Detecting When Motion Should Stop.

   During execution, a fixed step count may stop motion too early or waste
   steps on an unreachable target. Our move tool generates intermediate
   targets from measured poses and checks progress after each step (Figure
   5). This lets the tool adjust motion locally, stop on arrival, and
   return control when motion stalls or reaches an execution limit.
   Appendix D gives the algorithm and stopping criteria.

Making Action Outcomes Diagnosable.

   Reaching a target pose does not establish that an object was grasped or
   placed successfully. We return numerical motion feedback, including
   pose errors and stopping reasons, alongside images of the outcome
   (Figure 5). The numbers distinguish a small residual error from
   rejected or stalled motion; the images show the effect on the object.
   Together, they help the agent decide whether to refine the motion or
   change its manipulation strategy.

Managing Growing Visual Histories.

   This feedback accumulates, but old images may lose relevance while task
   instructions and action records remain useful. Our sliding window
   replaces old images with text placeholders, preserving recent images
   and the surrounding text (Figure 5). We evict images in batches to keep
   the prompt prefix stable between evictions and support cache reuse. If
   the context still exceeds budget, we compact the history with the same
   model that we use for the policy, using the compaction prompt of the
   codex CLI (OpenAI, 2026a).

3 Can Open Models Use Robots in Simulation and the Real World?

   Effective robot use has largely been the preserve of frontier,
   closed-source models. In this work, however, we show that open-weight
   models can also achieve competitive performance in simulation and on
   physical robots. In particular, on RoboDojo, Qwen3.8-Flash-Next
   surpasses most fine-tuned VLA and WAM baselines in a zero-shot setting
   without privileged information, and also the GPT-6 Astra’s result
   reported by the RoboDojo team. On real robots, a less-explored setting
   in prior works, open-weight models also achieve competitive
   performance, showing their real-world applicability. These results
   highlight the viability of open-source robot-use agents and the
   importance of a properly designed harness for supporting these models.

3.1 Simulation Evaluation

3.1.1 Setup

   We evaluate 42 RoboDojo (Chen et al., 2026a) tasks spanning
   generalization, memory, precision, long-horizon execution, and
   open-vocabulary instruction following. We report the success rate and
   the score (incorporating partial success, scaled to 0–100) following
   the RoboDojo’s evaluation protocol. The result is averaged over three
   seeds with two layouts (six episodes per task, 252 episodes in total).
   The 12 generalization tasks pair equally weight standard and randomized
   layouts per seed to test robustness to object and scene changes.
   Following the official protocol, we average the result of each tasks
   within the dimension, and average those results over the five
   dimensions.

   No Privileged Inputs. Our simulation uses the inputs of realistic
   robotics applications, providing only RGB images and camera
   calibration, robot proprioception and descriptions, and task
   instructions. We do not allow access to ground-truth depth from
   simulators, CAD assets of the object, hidden scene annotations,
   task-verifier feedback, and external web access. We also manually check
   that the models did not made any invalid access to the prohibited
   information throughout the experiment.

   To contextualize open-weight model performance, we compare against
   official Astra–RoboProbe (Zhang et al., 2026a) results and
   representative VLA and WAM baselines from the RoboDojo leaderboard
   (RoboDojo Team, 2026). To compare the contribution of the harness, we
   compare Qwen3.8-Flash-Next across uni-robot-agent, GAP (Hybrid) (Su et
   al., 2026), RoboProbe, and RPent (Zhang et al., 2026c). Baseline
   configurations are detailed in Appendix A.

4 What Capabilities Enable Robot-Use Agents?

   The results in Section 3 establish the feasibility of robot use with
   open-weight models, but leave an important question: what enables these
   models to work? To investigate this, we examine three comparisons.
   First, we revisit earlier model generations, including Qwen3.5–3.7 and
   GPT-5.6. Second, we compare recent models from different families,
   including Qwen, DeepSeek, GLM, and GPT. Third, we examine Qwen models
   of different sizes within the same generation.

   and Score using the same aggregation as Section 3. We reuse the Section
   3 results for Qwen3.8-Flash-Next, DeepSeek-V4.1-Flash, and GPT-6 Astra.
   The additional evaluations use one seed and one layout.

4.3 Four Major Failure Modes

   Our trajectory analysis identifies four major failure types: general
   visual understanding, such as misinterpreting objects or action
   outcomes; fine-grained pointing and spatial grounding, such as
   selecting inconsistent corresponding points across views; localization
   and pose computation code, involving errors in geometric calculations,
   coordinate transformations, or orientation construction; and embodied
   reasoning, such as proposing physically inappropriate grasp poses.
   Figure 7 summarizes these four failure types across thirteen models.

General visual understanding.

   Perhaps the most straightforward reason for failures in earlier Qwen
   Flash and Plus models is basic visual misunderstanding. Such errors,
   including mistaking zero for nine or inverted cups for upright ones,
   occur in 12.2–23.8% of trials. In contrast, these kinds of errors occur
   in 3.2% of Qwen3.8-27B trials and none of the trials from more
   performant models such as Qwen3.8-Flash or GPT-5.6 Sol. These
   observations suggest that general visual understanding is closely
   associated with its performance.

Spatial grounding.

   In addition to coarse scene understanding, we find that models struggle
   to pinpoint the same physical feature across camera views. Selecting
   inconsistent pixels for the same feature leads to large reprojection
   errors, causing the triangulation tool to reject the result. We
   therefore use the fraction of calls rejected for this reason to measure
   difficulty in pinpointing corresponding features. Task performance
   tends to be negatively associated with this failure rate: Qwen3.8-Flash
   and DeepSeek have lower failure rates than models with zero task
   success, including Qwen3.5–3.7 Flash and Qwen3.7 Plus. GPT-6.1 Sol
   achieves the lowest spatial-grounding failure rate among the evaluated
   models (31.5%), but this substantial remaining error rate highlights
   precise spatial grounding as a common challenge for further improvement
   (Figure 7b).

Coding in geometry

   Coding skill is also closely correlated with task performance, as
   illustrated by geometry computations involving coordinate
   transformations and orientations. Earlier Qwen models frequently
   reverse coordinate transforms or mix quaternion conventions, with such
   errors affecting 47.3–81.8% of executed calculations across the earlier
   Flash and Plus cohorts. In contrast, the error rates are 8.2% for
   Qwen3.8-Flash, 1.5% for DeepSeek, and 0.7% for GPT-5.6 Sol, with no
   errors in GPT-6.1 Sol’s calculations. The pattern suggests that
   reliable robot-specific computation is another capability associated
   with effective robot use (Figure 7c).

Embodied reasoning.

   Beyond perceiving and computing a target pose, robot use requires
   embodied reasoning to propose appropriate interactions, including grasp
   poses. Because this broad capability is difficult to measure, we
   restrict our analysis to pick-and-place and use GPT-6 Astra to assess
   whether proposed grasp poses are physically reasonable. We report the
   rate at which the model proposed unnatural or infeasible grasping poses
   and failed to correct them in these tasks (Figure 7d). To our surprise,
   even recent models can lack this capability: GLM repeatedly fails to
   reorient its wrist for grasping, contributing to many unsuccessful
   trials and a 26.2% error rate. Such errors are less frequent in newer
   Qwen and GPT models, which more often select appropriate grasp
   orientations. However, grasp-pose proposal is only one instance of
   embodied reasoning. GPT-6 Astra still struggles with other skills,
   including bimanual coordination, where inappropriate interaction plans
   limit performance. Embodied reasoning therefore appears to improve
   across model generations, but remains a substantial bottleneck beyond
   this narrow grasping analysis.

   In conclusion, these failure patterns suggest that effective robot use
   draws on a combination of visual understanding, spatial grounding,
   geometric coding, and embodied reasoning, rather than a single
   robot-specific capability. This suggests that general model
   capabilities provide a substantial foundation for robot use. We
   therefore argue that future RUA training should develop these
   capabilities jointly – for example, by using robot data to construct
   training tasks targeting each capability – rather than focusing solely
   on fitting action outputs.

4.4 Relationship to General Model Capabilities

   Having identified four key capabilities underlying effective robot use
   through failure analysis, we next ask: To what extent can these
   capabilities be captured by existing foundation-model benchmarks?

   To investigate this, we compare RoboDojo performance with scores on
   four corresponding benchmarks: MMMU-Pro (Yue et al., 2024) for general
   visual understanding, ERQA (Gemini Robotics Team et al., 2025) for
   embodied reasoning, ScreenSpot-Pro (Li et al., 2025) for spatial
   grounding, and LiveCodeBench v6 (Jain et al., 2024) for code generation
   (Figure 8). We observe positive correlations across all four
   benchmarks, with particularly strong correlations for embodied
   reasoning and general visual understanding, while spatial grounding
   exhibits a weaker correlation, potentially because ScreenSpot-Pro
   evaluates 2D screen-based grounding rather than the 3D spatial
   grounding required for robotic manipulation. These findings further
   support the role of general-purpose model capabilities in robot use,
   suggesting that advances in these capabilities may translate into
   improved robotic performance.

5 Analysis on Privileged Information

   As discussed in Section 2.4, privileged inputs such as precise
   simulator-provided depth and oracle task-success feedback can assist
   robot interaction. Although uni-robot-agent operates without these
   inputs, it remains important to understand how much they affect
   robot-use performance. We first challenge whether depth, a commonly
   used source of geometric information, is necessary for better
   performance (RQ1). Second, since skill libraries can encode privileged
   information or task-specific solutions, we ablate our skill library to
   test whether performance depends on such leak of privileged information
   (RQ2).

   through 771 tool calls and final score across 42 tasks, with skills
   enabled.

5.1 RQ1: How Does Depth Affect Robot Use?

   Figure 10: Effect of skill guidance on task performance.
   Qwen3.8-Flash-Next with uni-robot-agent, evaluated with and without
   skills. Error bars indicate approximate 95% bootstrap confidence
   intervals.

   We compare three levels of geometric information for depth: RGB images
   with depth and camera parameters, RGB images with camera parameters,
   and only RGB images. With depth and camera parameters, agent can infer
   3D coordinates directly from the pixel. Having only camera parameters
   requires the agent to find the pixel of corresponding points in
   multiple cameras. Without either, the agents should infer the
   coordinates through spatial relationships of the objects in the image.
   We evaluate GPT-6 Astra and Qwen3.8-Flash-Next on the same 42 benchmark
   tasks. The evaluation uses three seeds and two layouts per task for
   Qwen and one seed and one layout per task for Astra due to limited
   evaluation costs.

   Without depth, agents can still recover object positions with the
   camera parameters by triangulating the corresponding points across
   views. Evidently, Astra’s score changes from 55.83 to 55.04, and Qwen’s
   score changes from 35.89 to 31.39, retaining 98.6% and 87.5% of their
   depth-enabled scores, respectively (Figures 9 and 9), reflecting a
   minimal loss in performance, especially with stronger model
   capabilities. The cases in Appendix E further shows that Qwen writes
   and executes its own geometry code to infer 3D coordinates, such as
   triangulating object positions across views and testing candidate table
   heights with the images.

   Without camera parameters (only RGB images), where agents must infer 3D
   positions from abstract spatial relationships, Qwen’s performance shows
   a sharp drop to 9.13, while Astra shows a moderate decrease on its
   performance to 31.29 (Figure 9).

   In conclusion, we find that privileged depth information is not
   necessary for achieving strong robot-use performance as long as camera
   parameters are available. In fact, as model capabilities improve,
   models can more effectively infer 3D spatial relationships from visual
   observations, thereby benefiting less from such privileged inputs.

5.2 RQ2: Is skill library important for uni-robot-agent?

   Task-specific skill libraries may encode privileged information or
   predefined solutions that simplify robot tasks. We therefore examine
   whether the performance of uni-robot-agent depends on the knowledge
   provided by its skill library.

   Using Qwen3.8-Flash-Next, we disable access to the robot skill library
   and skill writing (we retain task instructions, environment
   descriptions, and standard robot tools). Figure 10 shows a small
   aggregate performance gap between configurations with and without robot
   skills. The no-skill configuration reaches 30.31 score and 24.58% SR,
   retaining 96.6% of the skill-enabled score (31.39), with an SR gap of
   only 0.42 percentage points. These results show that uni-robot-agent
   maintains comparable performance without the skill library. The harness
   supports reusable skills, but its robot-use performance does not depend
   on the task-specific knowledge they provide.

7 Related Work

Vision-Language-Action and World-Action Models.

   Vision-language-action (VLA) models extend robot policies beyond
   task-specific demonstrations by transferring pretrained visual-language
   representations and learning from diverse robot data (Brohan et al.,
   2023; Kim et al., 2024). Training on heterogeneous sources has further
   improved generalization:
   [MATH: <semantics><msub><mi>π</mi><mn>0.5</mn></msub><annotation
   encoding="application/x-tex">\pi_{0.5}</annotation></semantics> :MATH]
   performs manipulation in previously unseen environments by combining
   robot experience with semantic supervision and web data (Physical
   Intelligence et al., 2025). World-action models (WAMs) explore a
   complementary route through predictive modeling. Joint video and action
   generation enables DreamZero to generalize to unseen tasks and
   environments (Ye et al., 2026), while Cosmos Policy uses predicted
   future states and values to support test-time planning (Kim et al.,
   2026). These advances broaden where learned policies can operate and
   what behaviors they can perform. Reliable use of past observations and
   recovery from failures over extended interactions nevertheless remain
   important areas for further investigation.

Tool-Using Agents for Robot Control.

   Tool use allows language models to organize decisions around
   observations and feedback. In computer environments, agents operate
   graphical interfaces through repeated observation and action, combining
   visual grounding with planning and context management (Anthropic, 2024;
   Wang et al., 2025; Agashe et al., 2025). Robotics research has explored
   related ideas through skill selection and programmatic composition of
   perception and control APIs (Ahn et al., 2022; Liang et al., 2022).
   Environment feedback enables replanning (Huang et al., 2022), while
   spatial representations connect language instructions to physical
   motion (Huang et al., 2023). Together, these studies establish ways for
   general-purpose models to direct interaction through tools. In
   robotics, this interaction must also account for a world that changes
   while actions are running, making the coordination of observation,
   reasoning, and execution a central concern.

Robot-Use Agents and Harnesses.

   Recent studies show that general-purpose multimodal models can operate
   robots through tools without task-specific robot training (Isola, 2026;
   Zhang et al., 2026a). This has prompted efforts to design the harness
   through which a model observes the scene, issues actions, and receives
   feedback. RoboDawn and Robo-Harness K1 provide motion and geometric
   perception tools (Guo et al., 2026; Li et al., 2026), while OpenRUA
   gives coding agents access to native ROS 2 interfaces through a
   terminal (Chu et al., 2026). Beyond these interfaces, Harness VLA and
   GAP investigate how agents can guide learned policies through
   memory-based planning and corrections to policy-generated actions
   (Zhang et al., 2026c; Su et al., 2026). ORA also demonstrates robot use
   with open-weight models, combining robot tools with environment
   information and context management (Yang et al., 2026). As robot use
   expands to more models and environments, reusing these components
   becomes an important system-design question. We develop uni-robot-agent
   around this need, separating shared robot tools from model runtimes and
   environment adapters so that changing one does not require rebuilding
   the others. We also coordinate tool execution and feedback to let
   agents continue reasoning while physical actions are underway.

8 Conclusion

   We presented uni-robot-agent, a unified and modular harness with
   efficient execution and reliable tools for robot-use agents.
   Evaluations demonstrate strong performance with GPT-6 Astra in both
   simulation and real-world manipulation. More importantly, our results
   show that an open-weight model can also achieve strong robot-use
   performance: Qwen3.8-Flash-Next reaches a RoboDojo Score of 31.39,
   exceeding the published Astra–RoboProbe result of 28.97. These findings
   support further investigation of open-weight models that can be
   deployed locally and adapted through training on robot experience.
   Precise manipulation and reliable long-horizon execution remain
   challenges in our evaluations. By providing shared interaction
   interfaces, replaceable components, and structured execution feedback,
   uni-robot-agent offers a unified foundation for collecting robot
   interaction data, developing training methods, and evaluating their
   effects on agent behavior and task performance.

Appendix B Real Eval Benchmark Details

   Real Eval evaluates tabletop manipulation on a dual-arm gripper
   platform through five capability dimensions: spatial understanding,
   object generalization, instruction following, compositional
   generalization, and unseen tasks. Its test catalogue contains 19
   evaluation entries, with 20 points allocated to each dimension and 100
   points in total. An evaluation entry specifies an operation together
   with the variation being tested: bowl stacking, for example, appears
   both as an object-generalization test and as a direction-following
   test. The catalogue therefore distinguishes changes in objects,
   language, and task structure even when they share a manipulation
   primitive. Table 3 gives the complete test catalogue and its scoring
   criteria.

B.1 Hardware and Baselines

   All methods run on an ARX AC one dual-arm platform with two X5 arms and
   three Intel RealSense D405 cameras, comprising a head view and a wrist
   view on each arm. We evaluate uni-robot-agent with GPT-6 Astra and
   Qwen3.8-Flash-Next as planners and compare both configurations with
   [MATH: <semantics><msub><mi>π</mi><mn>0.5</mn></msub><annotation
   encoding="application/x-tex">\pi_{0.5}</annotation></semantics> :MATH]
   (Physical Intelligence et al., 2025), fine-tuned on demonstrations from
   the same platform. We also include Dream-1 (Dream Labs, 2026), a world
   action model evaluated zero-shot through its public API
   (dreamlabs/dream-1-beta). In the real-world evaluation, uni-robot-agent
   additionally uses the D405 depth stream, whereas
   [MATH: <semantics><msub><mi>π</mi><mn>0.5</mn></msub><annotation
   encoding="application/x-tex">\pi_{0.5}</annotation></semantics> :MATH]
   and Dream-1 natively consume only RGB images.

B.2 Training Task Catalogue and Collection Protocol

   The accompanying training catalogue lists 30 task templates and 1,550
   trajectories: 27 templates specify 50 trajectories each, while bag
   zipping, coin insertion, and tissue extraction specify 100, 80, and 20,
   respectively. The templates span stacking and sorting, object transfer
   and handover, container loading, cloth manipulation, surface wiping,
   and operation of buttons, switches, drawers, and a microwave door.
   Collection protocols vary object placement, material, color, container
   arrangement, and table appearance at task-specific intervals. For
   example, paper-cup stacking uses four to six inverted cups at different
   positions, changes cup material every five trajectories, and changes
   the table mat every ten. Test-tube transfer uses three to four tubes of
   different sizes and reverses the transfer direction every five
   trajectories. Cloth folding includes two folds per trajectory, changes
   cloth orientation every three trajectories, and changes the cloth every
   six. These collection settings establish the reference operations and
   variations against which the test catalogue defines new objects,
   instructions, and action combinations. The catalogue is collected to
   fine-tune end-to-end embodied policies such as
   [MATH: <semantics><msub><mi>π</mi><mn>0.5</mn></msub><annotation
   encoding="application/x-tex">\pi_{0.5}</annotation></semantics> :MATH]
   , whereas uni-robot-agent does not use any of these demonstrations; for
   uni-robot-agent, every entry is therefore evaluated zero-shot, and the
   five dimensions characterize the type of variation that each entry
   introduces.

B.3 Evaluation Dimensions

Spatial understanding.

   This dimension includes one simple entry (fruit transfer), two
   intermediate entries (cloth folding and plate extraction), and two
   complex entries (test-tube transfer and mug hanging). Fruit transfer
   moves cherries, bananas, apples, oranges, and melons from bowls or
   plates into a basket. Cloth folding varies size and orientation. Plate
   extraction requires one arm to lift a bottle while the other removes
   and stacks the plate beneath it. Test-tube transfer and mug hanging
   further distinguish acquiring an object from completing the subsequent
   placement.

Object generalization.

   The operation remains bottle handover or bowl stacking while the
   manipulated objects change. Handover introduces tea, coconut-water, and
   bottled-water containers, together with handled stainless-steel and
   plastic cups. Bowl stacking introduces stainless-steel bowls, small and
   large paper bowls, ceramic bowls, and large salad bowls. These
   variations probe differences in shape, size, material, and available
   grasp geometry.

Instruction following.

   Three tests separate color, object, and spatial-language grounding.
   Color-conditioned cup stacking places two or three differently colored
   cups on the table and specifies which color should be stacked onto
   which other color. Object-conditioned pick-and-place uses a toy car,
   five fruit types, blocks, and three tableware types, with bowls,
   plates, and baskets as target containers. Direction-conditioned bowl
   stacking requests left-to-right or right-to-left arrangements. These
   tests evaluate whether a physically feasible operation is directed
   toward the requested object, destination, and spatial relation.

Compositional generalization.

   Four entries recombine familiar operations, objects, and semantic
   constraints. Tissue extraction followed by disposal chains two actions
   into one objective. Stacking upward-facing cups changes the object
   configuration relative to the inverted-cup training template. Wiping a
   whiteboard with a rag combines the wiping operation with an object used
   elsewhere in the task catalogue, replacing the whiteboard eraser
   specified for training. Arranging cubes by color changes the criterion
   from the size ordering specified in the training catalogue. Together,
   these cases test action sequencing, object substitution, and semantic
   recombination.

Unseen tasks.

   The final dimension organizes transfer by its relation to the training
   catalogue. Closing the microwave door isolates a sub-action of the
   microwave loading routine. Taking a bowl out of the microwave and
   unfolding a rag reverse the corresponding loading and folding
   operations. Stacking books is listed as a combined action, while
   building a three-level Tower of Hanoi is listed as a new action.

Appendix D Monitored Motion Execution

   The execution monitoring described in Section 2.5 addresses a basic
   difficulty in robot control: issuing a motion command does not
   establish that the robot has reached its target. Planning may reject a
   command, or execution may stop making progress. The move tool therefore
   advances through bounded waypoints, checks the state returned after
   each step, and reports why execution ended so that the agent can decide
   what to do next.

Planning rejections and feedback.

   A planning rejection may allow the tool to try a nearby execution
   target without relaxing the agent’s original request. On backends that
   support goal-region search, EligibleGoalSearch permits one search per
   move call following an active-arm rejection of type ik_failed,
   joint_jump_rejected, or ik_candidate_rejected. An alternative goal is
   accepted only if it refers to the current state version and lies within
   the original position and orientation tolerances. It replaces
   [MATH: <semantics><mover
   accent="true"><mi>g</mi><mo>~</mo></mover><annotation
   encoding="application/x-tex">\tilde{g}</annotation></semantics> :MATH]
   and resets the progress history, while arrival continues to be checked
   against
   [MATH: <semantics><mi>g</mi><annotation

   The returned feedback tells the agent where the robot ended up, how far
   it remains from the requested pose, and why execution stopped. It
   includes actual and target poses, position and orientation errors,
   arrival status, accepted-step count, and available rejection or
   recovery diagnostics. Reaching a pose does not by itself establish that
   a grasp, placement, or other task objective has succeeded.

Appendix E Spatial Grounding Through Agent-Written Code

   Refer to caption Figure 15: Agent-written triangulation in
   insert_tubes. Matching pixels marked A define viewing rays, illustrated

   reprojection errors connect the calculation to its output; the final

   The depth ablation in Section 5.1 raises a practical question: how does
   an agent obtain usable spatial coordinates when its observations
   contain no depth? We examine two successful Qwen3.8-Flash-Next episodes
   from the no-depth, no-skill configuration. In both, the agent writes
   and executes geometry code using RGB observations and the supplied
   camera intrinsics and extrinsics, rather than calling the built-in
   triangulation operation. The cases illustrate different ways of
   constructing localization estimates: matching features across views and
   testing geometric assumptions against image evidence.

E.1 Recovering Tube Positions Across Views

   In insert_tubes, the agent must place three tubes into a rack. After
   obtaining image-space segmentation boxes, it captures additional camera
   views and writes a Python function to intersect viewing rays in a
   least-squares sense. It then selects corresponding tube-cap pixels and
   computes their world coordinates. Figure 15 follows one cap: the
   calculated position reprojects within 0.46 and 1.94 pixels of the
   selected points in the two views. This gives the agent a way to check
   whether its chosen correspondences agree geometrically.

   The cap positions are only the beginning of the manipulation sequence.
   The agent subsequently estimates tube axes, chooses grasp poses, and
   uses observations and action feedback to guide lifting and insertion.
   The episode ends with all three tubes in the rack. Here, code execution
   turns image correspondences into coordinates that the agent can inspect
   and use in its action planning.
   Refer to caption Figure 16: Geometric hypothesis testing in
   cover_blocks. The agent varies a candidate table height and computes
   cup dimensions from selected pixels. The schematic illustrates the
   ray–plane intersections computed by hit() in the code excerpt; the
   right-hand frame shows a later placement over the red block.

E.2 Exploring Geometry Before Moving a Cup

   In cover_blocks, the agent must cover three colored blocks from left to
   right, then uncover them in a specified color order. Locating the cups
   requires reasoning about their extent as well as their image centers.
   The agent extracts colored image regions and writes code that tests
   candidate table heights, intersects pixel rays with each candidate
   plane, and compares the resulting cup dimensions (Figure 16). The
   height sweep exposes how an assumed scene parameter changes the
   inferred geometry, rather than treating a single image estimate as
   fixed.

   The agent continues by projecting candidate object shapes into the
   images and refining its scene estimates. It then uses the estimated cup
   positions to approach, grasp, and place the cups, checking the scene as
   the task proceeds. The recorded episode completes the required covering
   and uncovering sequence. This case shows a more exploratory use of
   code: the agent constructs and tests geometric hypotheses before
   committing to physical actions. Together, the two cases illustrate how
   RGB-based localization can support successful execution, while
   requiring correspondence selection, geometric assumptions, and
   verification that depth access can simplify.
